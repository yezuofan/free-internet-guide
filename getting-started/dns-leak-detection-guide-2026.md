# DNS 泄漏怎么查：三个检测站、五个漏点，开着代理也可能在漏

> 节点连上、网页能开、测速好看——然后一跑检测站，DNS 服务器列表里写着你家宽带的名字。这就是 DNS 泄漏：它不断网也不卡，但把你在查什么、人在哪，全告诉了本地运营商。更麻烦的是解析这一层还走本地，污染就能绕过你那个看起来很稳的节点生效。

**更新时间：2026年11月25日**

---

## 一、先分清两个词：污染是「错」，泄漏是「被看见」

| | 是什么 | 症状 | 什么时候能发现 |
|:--|:--|:--|:--|
| DNS 污染 | 解析结果被改成错的 | 打不开、跳广告、跳备案页 | 立刻发现，不查也得查 |
| DNS 泄漏 | 解析请求没走代理，本地运营商看得见 | 网页照开，速度照好 | 不主动查，一辈子不知道 |

危害三条：账号风控（出口 IP 在美国、解析从广州发出，一致性问题给了降权依据）；流媒体地区判定拧巴；最要命的是污染绕过——你配的加密解析被一条没锁的窗废掉。

## 二、三个检测站，各看哪一块

原理很朴素：这些站让你加载一批随机子域名，看是哪个解析器跑来问。谁来问，你的 DNS 就归谁管。

- **browserscan 的 DNS 泄漏页**：结果最直白，把出口 IP 和 DNS 归属并排放，同不同国一眼看出。
- **dnsleaktest**：Extended Test 值得多点一次。Standard 只发一两轮，刚好都走代理时会被骗过。
- **ipleak**：看「DNS Addresses」那块，顺手把 WebRTC 泄漏一起看了。

**别只信一个站。** 探测域名、轮次、判定逻辑都不同，一家说干净另一家说漏的情况我遇到过不止一次。

## 三、结果怎么读

判断标准只有一条：**这些服务器的归属，和你家宽带运营商是不是同一家。**

| 列表里看到 | 判读 |
|:--|:--|
| 电信 / 联通 / 移动，或一串国内 IP 段 | 典型泄漏，解析还在走本地 |
| Cloudflare / Google / 阿里云 / 腾讯 | 大概率正常，解析确实进了加密通道 |
| 你的节点 IP 或机房名 | 最理想，解析走了代理 |
| 一堆陌生机构、分布多国 | 客户端在做上游轮询，不是故障 |

容易误判的一点：**出现一个国内 DNS 不等于全漏。** 国内域名走国内 DNS 为了快、国外走加密通道，这是分流在正常工作。看比例——清一色国内才是漏。

判断不了就关掉代理再跑一次：两次结果一样，说明 DNS 从没被接管过。

## 四、五个漏点

**1. 客户端压根没接管 DNS。** 最常见。DNS 总开关没开、fake-ip 没启用，域名交给系统解析，系统解析器就是运营商那台。

**2. IPv6 从旁边溜走。** 国内宽带普遍下发 IPv6，很多客户端只接管 IPv4。系统优先用 IPv6，DNS 查询就从那条路直连出去了。修法两条：客户端里关掉 IPv6 解析，或者开 TUN 并显式打开 IPv6 支持，让 v4/v6 一起走代理。

**3. 浏览器自带的安全 DNS 在打架。** Chrome/Edge 的「使用安全 DNS」、Firefox 的 DoH 工作在浏览器内部，会盖过系统设置。未必泄漏给运营商，但会打乱分流规则、让 fake-ip 失效。配完客户端一定要去浏览器确认这个开关。

**4. 多网卡并行查询。** 典型场景是插着网线又连 Wi-Fi，或 TUN 虚拟网卡与物理网卡共存。Windows 的智能多宿主名称解析会同时向所有网卡 DNS 发查询，物理网卡那一路直连运营商。修法：关掉这个机制，或把物理网卡 DNS 手动指到内部地址。

**5. 非浏览器应用直接连。** 不开 TUN 时系统代理只对部分应用有效。游戏客户端、下载工具、curl/​git、某些软件的更新模块直接查 DNS，完全绕过代理。这类只能上 TUN 做全局接管。

## 五、客户端怎么写（核心是四件事）

开 DNS、开 fake-ip、给代理服务器自己留一条直连解析、国内域名单独走国内 DNS。

```yaml
dns:
  enable: true
  ipv6: false
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  fake-ip-filter: ['*.lan', '+.msftconnecttest.com']
  default-nameserver: [223.5.5.5, 119.29.29.29]
  nameserver:
    - https://1.1.1.1/dns-query
    - https://dns.google/dns-query
  proxy-server-nameserver:
    - https://dns.alidns.com/dns-query
  nameserver-policy:
    'geosite:cn,private':
      - https://dns.alidns.com/dns-query
      - https://doh.pub/dns-query
```

上面这段是 Clash Verge Rev / Clash Party（同为 Mihomo 内核）的写法。几个键的分工比抄配置重要：

- `nameserver` 默认解析器，走代理，填加密 DNS 别填裸 IP。
- `proxy-server-nameserver` **专门解析机场订阅域名本身，必须能直连**。填错会出现「连节点都连不上」——那一步还没有代理可用。这是新手最容易踩的坑。
- `nameserver-policy` 分流。国内域名交给阿里、腾讯，快且不浪费代理流量。
- `fake-ip-filter` 必须放行局域网和系统网络探测域名，否则连 Wi-Fi 的认证页会失效。

其它客户端要点：**Stash** 用 `nameserver` + `fallback`（主用国内、兜底国外加密）；**Shadowrocket** 图形界面里开 DNS 覆写填加密地址，顺便把 IPv6 关掉；**sing-box** 用 `dns.servers` 的 `detour` 字段区分 `direct` / `proxy`，再按 geosite 分流。

## 六、改完必须复测

1. 完全退出客户端再重开（不是关窗口，DNS 缓存活在系统里）。
2. 浏览器无痕窗口打开检测站（普通窗口有缓存和 Service Worker）。
3. 三个站再跑一遍，看列表里还有没有国内运营商的名字。

合格结果：列表里全是公共加密解析商或节点落地 IP。还漏的话，先确认改的是当前生效的那份配置——客户端有多个配置档案，改错文件很常见。

## 七、什么时候不用折腾

只用浏览器且开了安全 DNS 的；客户端把 DNS 全托管、用户碰不到配置的；在公司或校园网里 DNS 被强制接管的。这三种改了收益都很小。

真正该查的是三类人：经常登录海外账号的、做跨境生意的、对「我在哪」敏感的。查一次五分钟，收益是长期的。
