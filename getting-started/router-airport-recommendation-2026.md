# 软路由机场推荐：先量路由器，再挑机场，五个硬指标（2026）

## 一、软路由上，排序为什么全变了

客户端跑代理，CPU 是 i5 或者 A17，内存 8GB 起步，一百个节点毫无压力。路由器跑代理，CPU 是四核 A53 甚至双核 MIPS，内存 256MB 到 2GB，还要同时干拨号、NAT、无线、DHCP、QoS。

判断标准从「哪家线路好」变成「哪家线路好，而且不给这台机器增加太多负担」。负担来自五处：节点条数（占内存 + 周期性健康检查）、加密协议（吃单核）、订阅形态（能不能直接读）、UDP 转发（吃 conntrack）、设备数怎么算。

## 二、先量三个数字

```bash
free -m | head -2
nproc && grep -m1 'model name\|Processor\|cpu model' /proc/cpuinfo
top -b -n1 | grep -iE 'clash|mihomo' | head -5
```

第三个是吞吐，必须自己测：同一条线路，直连和走代理各跑三次取中位。直连九百多兆、走代理掉到两百兆的机器不算少见——那不是线路差，是用户态转发绕开了硬件 NAT 加速。

| 档位 | 典型硬件 | 内存 | 真实代理吞吐量级 |
|:--|:--|:--|:--|
| 入门 | MT7621 双核 880MHz 刷 OpenWrt | 128–256MB | 百兆出头就吃紧 |
| 主流 | MT7981 / N1 盒子旁路由 | 256MB–2GB | 三五百兆，看协议 |
| 充裕 | N100 / J4125 四口 2.5G | 4–16GB | 千兆以上，瓶颈回到线路 |

结论很直白：入门和主流档上，机场标的「1000Mbps」对你没有意义。花钱买带宽，不如花钱买省 CPU 的协议。

## 三、硬指标一：节点条数不是越多越好

订阅一贴进去，OpenClash 会把整个配置读进内存，再按间隔对全部节点做延迟测试。110 条就是 110 个并发请求轮一遍，330 条就是 330 个。4GB 机器上叫「无感」，256MB 路由器上叫「定时卡顿」，运气不好 conntrack 表和内存一起见底。

| 机场 | 节点/线路规模 | 弱机器友好度 |
|:--|:--|:--|
| [WGetCloud](https://api.huanghaiwan.com/go/getcloud) | 基础 15 个、精品 29 个 | 最友好 |
| 自由猫 | 按档位 30 / 60 / 110 条 | 档位越贵越吃力 |
| SS-ID | IEPL 专线，不按数量卖 | 友好 |
| 仙路湾 | 20 个地区 | 友好 |
| 新华云 | 按 VIP 等级分节点池 | 中等 |
| 悠兔 | 119 条以上 | 中等偏重 |
| TAG | 330+ 条，覆盖 100+ 国家/地区 | 最重，必须分组 |
| 扬帆云 | 按等级分池，LV4 起含全 IEPL | 中等 |

节点多不是错，但必须配分组。在 `proxy-provider` 里加 `filter`，只把几个常用地区放进 `url-test`：

```yaml
proxy-providers:
  airport:
    type: http
    url: "你的订阅地址"
    interval: 3600
    health-check:
      enable: true
      url: https://www.gstatic.com/generate_204
      interval: 600
    filter: "(?i)(香港|HK|日本|JP|新加坡|SG)"
```

这一行把 330 条砍到 40 条以内。`interval: 600` 也别写太小，300 秒一轮在弱机器上就是每五分钟卡一次。

## 四、硬指标二：加密方式吃掉多少单核

所有流量都要在路由器上做一次加解密，这个运算只能落单核，多核帮不上。开销从低到高：

- **Shadowsocks（AEAD）**：最省。`aes-128-gcm` 在带 AES 指令集的 ARMv8 上走硬件加速，`chacha20-ietf-poly1305` 在没有 AES 加速的老 MIPS 上更快。TAG 全线就是 Shadowsocks。
- **SS-Obfs / Trojan Plus**：中等，多一层混淆或 TLS 包装。自由猫全线是这两个协议。
- **Trojan / VLESS + TLS / Reality**：偏重，每包都要过一遍 AEAD。N1 上三五百兆没问题，MT7621 上别指望。
- **Hysteria2 / TUIC（QUIC 系）**：最重也最挑环境。UDP 用户态实现，CPU 开销明显高于 TCP 系；还要求 UDP 转发链路通畅、conntrack 够用。Cyberguard 是自研 QUIC 栈，官方标注单线程吞吐≥300Mbps——「单线程」就是在说吃满一个核。

手上是 256MB 老路由，优先找标 SS 或 SS-Obfs 的机场，别一上来追 QUIC。

## 五、硬指标三：它给不给 Clash 能吃的订阅

OpenClash 要 Clash 格式的 YAML。给的是 `ss://` 或者 Base64 列表，就得在路由器上再挂订阅转换，或者开「在线订阅转换」——后者等于把订阅地址交给第三方服务器。

更麻烦的是压根不给订阅。这里必须点名，因为我们自己的总表里它排第一：**自由猫**。它每个套餐说明都写着「不提供订阅链接、不支持第三方客户端」，靠自家客户端登录，手机电脑上体验不错、价格也低（¥8 起 30GB），但软路由这条路走不通。它合适的人是「一个人两三台设备」，不是「全家一个出口」。

买之前问三句：有没有 Clash/Mihomo 格式的订阅地址（不是「支持 Clash」，是「给 YAML」）；这个地址会不会定期换；有没有「同时在线」限制、家里设备多会不会被判共享。

## 六、硬指标四：UDP 转发行不行

TCP 能通不等于 UDP 能通。游戏、语音、视频会议、部分 DNS 查询都走 UDP，而 UDP 在用户态代理里最容易出问题。症状：网页秒开、Steam 联机转圈；微信语音能用、Teams 一进会就没声；Switch 报 NAT 类型 D。

没有普适答案，各家支持程度不同、同家不同节点也可能不同。能做的两件：买前问一句「UDP 全节点支持吗」；买后用具体场景验，别只用测速软件——它跑的绝大多数是 TCP。

## 七、硬指标五：设备数在 NAT 之后怎么算

这条反直觉但对你有利。大多数机场的「设备数」按同时在线 IP 算（v2board 系面板默认口径），软路由 NAT 之后全家只有一个出口 IP——电视、电脑、每台手机，对机场来说都是同一台设备。

所以「3 台设备」在软路由场景下往往不是三台，而是「一个出口」。但有两个例外：有些机场按连接数或节点并发计，不看 IP；你在软路由上开了多 WAN、多拨，或者旁路由和主路由各跑一份代理，就会被算成两个。买前问清楚「按 IP 还是按连接数」。

## 九、三套典型硬件怎么搭

- **256MB 老路由（MT7621 一代）**：目标不是快是稳。选节点少的（WGetCloud 基础、SS-ID、仙路湾），协议优先 SS 系，关掉负载均衡和全量健康检查，分组只留三四个地区。稳定跑两百兆上下、全家刷视频不卡，这台机器就算干得不错。
- **N1 盒子 / 小主机旁路由（2GB 左右）**：最常见的配置。瑶瑶领先这类大流量档接住日常流量，再挂一个仙路湾或 SS-ID 做备用——是备用不是同时开，同时开两份代理在旁路由上会打架。节点数控制在 100 条以内。
- **N100 / J4125 四口小主机做主路由（4GB 以上）**：机场才是真正的瓶颈。可以玩 TAG 的 330 条、上 QUIC 系协议、给不同设备分不同出口，值得直接上专线档。

两条基础活先做掉：光猫改桥接、MTU 调对。桥接的坑（IPTV 断流、改坏怎么救）见[光猫改桥接实操](https://huanghaiwan.com/posts/fiber-modem-bridge-mode-guide-2026/)；隧道封装吃掉的那几十字节不调，就会出现「能打开网页但下载卡住」，细节见 [MTU 与 MSS](https://huanghaiwan.com/posts/mtu-mss-fragmentation-guide-2026/)。

## 十、五个坑

1. **所有节点塞进一个 `url-test` 组**：健康检查每轮几百个请求，路由器定时卡顿；自动切换还会让出口 IP 频繁漂移，账号被踢、支付被风控。
2. **弱机器上开在线订阅转换**：转换在远端跑，但每次更新都要拉一次长列表，解析 YAML 那一下最容易爆内存。能直出 YAML 就别转。
3. **把「千兆网口」当成「千兆代理」**：中间隔着一次 CPU 加解密，掉多少取决于单核性能。
4. **旁路由和主路由都开着 DHCP**：症状是「有时能上有时不能上」，全网只留一个 DHCP，旁路由只做网关。
5. **买了不给订阅的机场**：钱花了、服务也没问题，就是装不进路由器。

## 十一、常问的

**软路由要不要开 TUN？** 只代理浏览器和常见 App，规则模式够用；要接管游戏主机、电视盒子，或者某些不认系统代理的客户端，才需要 TUN。代价是所有流量进隧道，CPU 和 UDP 问题一起放大。

**256MB 能跑 1000Mbps 的机场吗？** 跑不满。标称是上限，实际由加解密速度决定。同一条线在 N100 上八九百兆，换老路由可能只有两百兆，差的是机器。

**「不限设备」在软路由下面连二十台怎么算？** 按 IP 只算一台（都在同一出口）。按连接数或并发节点算就是二十份压力，这条必须问客服。

**节点延迟一片绿为什么还卡？** 延迟只测一小段 TCP 握手，测不到长连接稳定性和吞吐。软路由上尤其如此，`top` 看一眼 CPU 占用就知道。

**换机场能解决卡顿吗？** CPU 长期 80% 以上，换十家都一样；只有 20% 还卡，那才是线路问题。
