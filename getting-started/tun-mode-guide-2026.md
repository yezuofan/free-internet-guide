## 为什么有些 App 不走代理

系统代理是「通知型」的——它只在系统设置里写了一个代理地址，应用愿不愿意读取决于应用自己。典型的「不走系统代理」选手：

- **游戏**：Steam、Epic、战网。流量大量走 UDP，而系统代理主要面向 TCP，游戏普遍不实现代理逻辑
- **命令行工具**：`git`、`npm`、`pip`、`curl`、`ssh` 默认直连
- **Windows UWP 应用**：沙箱应用读取系统代理受限
- **系统级服务**：Windows Update、系统遥测

所以会出现「浏览器能用、别的不能用」的割裂——不是线路问题，是流量根本没进代理通道。

## TUN 模式是什么

TUN（Network Tunneling）模式创建一张**虚拟网卡**并修改系统路由表，把流量引导进网卡，由客户端统一处理后转发到线路。

| 对比项 | 系统代理 | TUN 模式 |
|:----|:----|:--------|
| 接管范围 | 只接管「愿意读设置」的应用 | 全部 TCP/UDP 流量 |
| 是否需要应用配合 | 需要 | 不需要（内核级接管） |
| UDP 流量 | 基本不支持 | 支持 |
| 适用场景 | 浏览器为主 | 游戏、命令行、全场景 |

**换成人话：** 系统代理像在小区门口贴通知「去国外的走这边」，看不看随你；TUN 模式像直接把整条路改道——不管知不知道，流量都从这条道走。

**一个高频误区：TUN ≠ 全局模式。** TUN 决定「流量能不能被接管」，规则模式决定「接管后哪些走代理、哪些直连」。正确组合是 **TUN + 规则分流**——国内流量直连，国外走线路，游戏流量进 UDP 通道。直接切全局反而让国内网站绕路变慢，还可能触发银行/购物 App 风控。

## 各客户端开启 TUN 的步骤

### Clash Verge Rev（Windows / macOS）

1. 左侧「设置」→ 找到 **TUN 模式**，打开开关
2. Windows 首次开启提示安装服务（需管理员权限）；macOS 请求添加虚拟网卡权限
3. 建议同时开启「自动设置系统代理」

### ClashX Pro（macOS）

菜单栏图标 → 设置 → 打开 **增强模式（Enhanced Mode）**（即 TUN 的另一种叫法），首次需输入管理员密码。

### Stash（iOS / macOS）

首页「设置」→ 打开 **TUN 模式**。iOS 首次开启会提示「允许添加 VPN 配置」，务必点允许——不装描述文件 TUN 无法工作。

### Shadowrocket（iOS）

右上角「设置」→ 打开 **TUN 模式**相关开关，首次同样需允许添加 VPN 描述文件。注意「全局路由」是策略选择、TUN 是接管方式，两者是不同概念。

### sing-box / FlClash / v2rayN（进阶）

- **sing-box**：配置文件加 `"tun": {"enable": true}` inbound
- **FlClash**：设置 → TUN 模式，Android 会请求 VPN 权限
- **v2rayN**：设置 → 勾选 TUN，首次需以管理员身份运行安装驱动

**通用注意：** Windows 需管理员权限或已安装服务（右键「以管理员身份运行」）；macOS/iOS 授权弹窗必须允许；开启后建议同步配置 DNS。

## 常见问题与避坑

| 问题 | 解法 |
|:----|:----|
| 开 TUN 后网络全断 | 与杀软/防火墙驱动冲突：关 TUN 确认恢复 → 加白名单 → Windows 确认以管理员运行过 |
| DNS 泄漏/解析变慢 | 开启 fake-ip 模式（Clash 系默认）；DNS 分流：国内走 AliDNS/DNSPod，国外走 1.1.1.1/8.8.8.8 DoH |
| 国内 App 变慢被风控 | 确认在规则模式（Rule）不是全局（Global），国内流量保持直连 |
| 开热点共享时 TUN 失效 | 热点共享改路由表与 TUN 冲突；设备直接装客户端，或走路由器网关方案 |
| 游戏能连但很卡 | 确认节点支持 UDP、换低延迟节点；晚高峰选 IEPL 专线 |
| 耗电/性能 | 转发层开销很小；续航敏感或下载大文件时可临时关 TUN |

## FAQ

**Q1：TUN 和全局模式是一回事吗？**
不是。TUN 是接管方式（流量进不进虚拟网卡），全局/规则是策略（接管后走不走代理）。推荐 TUN + 规则分流。

**Q2：开了 TUN 还需要系统代理吗？**
建议都开。TUN 接管绝大部分流量，系统代理让「只读系统代理」的应用也能识别，兼容性最好。

**Q3：iOS 上 TUN 和 VPN 图标是一回事吗？**
开启 TUN 时 iOS 会创建 VPN 配置描述文件，状态栏出现 VPN 图标是正常的。关掉 TUN 后图标消失。

**Q4：开了 TUN 某款游戏还是连不上？**
确认 TUN 真在生效、游戏流量没被规则误判直连、节点支持 UDP、服务器地区有可用线路。个别游戏反作弊驱动与 TUN 冲突需特殊处理。

**Q5：TUN 模式安全吗？**
TUN 只负责接管流量，加密转发仍由客户端和线路完成，安全性取决于线路协议（Trojan/VLESS/Reality 等），开 TUN 不降低加密强度。

**Q6：怎么确认 TUN 真的生效？**
开一个之前连不上的命令行工具：`curl -I https://www.google.com` 或 `git ls-remote https://github.com/xxx`，能通就是生效。

## 总结

「部分应用不走代理」的根因是系统代理只对「愿意配合的应用」生效。TUN 模式用虚拟网卡接管全部流量，是游戏、命令行、桌面客户端连不上的标准解法。三个要点：**开 TUN 不等于切全局**（保持规则模式）；**首次开启注意权限**（Windows 管理员、macOS/iOS 授权弹窗）；**DNS 配合 fake-ip + 分流**。
