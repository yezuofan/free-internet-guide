# Claude Haiku 5.5 上手指南 2026：单价砍掉九成，但换了个分词器会让账单多算三成

**2026 年 10 月更新。** Anthropic 于 **10 月 7 日**发布 Claude Haiku 5.5，是 Claude 5.5 家族第三款（9 月 22 日 Opus 5.5 → 9 月 28 日 Sonnet 5.5 → 10 月 7 日 Haiku 5.5，半个月补齐）。10 万 token 以内输入 $0.10 / 输出 $0.50（每百万 token），较上代降 90%；上下文从 20 万拉到 100 万 token。**但新分词器让同样文本多算 25%–30% 的 token，官方自己算的综合成本降幅是约 75%。**

## 一、规格与价格：三条边界

| 项目 | Haiku 4.5 | Haiku 5.5 |
|:---|:---|:---|
| 上下文窗口 | 20 万 token | **100 万 token** |
| 最大输出 | 6.4 万 token | **12.8 万 token** |
| 输入（≤10 万 token） | $1.00 | **$0.10**（降 90%） |
| 输出（≤10 万 token） | $5.00 | **$0.50**（降 90%） |
| 输入 / 输出（>10 万 token） | $1.00 / $5.00 | $0.50 / $2.50（降 50%） |
| 缓存读取 | $0.10 | **$0.01** |
| 推理强度 | 无 | **支持 `effort` 调节** |
| 浏览器操作 | 无 | **Browser Use** |

**边界一：10 万 token 是台阶不是滑梯。** 一超线单价就跳到基础价的 5 倍。官方数据：Haiku 4.5 约 90% 的请求都在 10 万以内，所以日常活吃得到最大折扣——但「整篇长文档灌进去」恰好属于另外那 10%。

**边界二：输出比输入贵 5 倍。** 所以「让 Haiku 写长文」和「让 Haiku 从材料里抠字段」是两种成本结构，后者才吃得到最便宜的输入价。

**边界三：缓存便宜要用对。** 缓存读取降到上代十分之一，适合「同一份背景材料反复问不同问题」；命中率低这条优惠等于不存在。

同期 Sonnet 5.5 的缓存读取也砍半（$0.20 → $0.10），官方口径是多数智能体任务便宜约两成。

## 二、最容易被忽略：换分词器，同样一段话多算 25%–30% token

这是本轮发布里最不该漏掉的细节。Haiku 5.5 用上了与高端模型同款的新分词器，**同样一段文本切出来的 token 数比上一代多 25% 到 30%**。

两件事叠在一起：单价降 90%，计费单位多两三成 → 真实综合降幅 **约 75%**（Anthropic 官方口径用的也是这个数，价格页上更醒目的 90% 说的是单价）。

它改变了成本估算的基线：照 90% 拍脑袋以为成本变成 0.1X，实际会落在 0.25X 附近。**自查办法是别估算、去数**——拿你真实会发出的输入（中文夹杂英文术语那种），两代各数一遍 token。中文场景偏差通常比英文更明显。

| OSWorld 2.1（操作电脑） | 15.7% | **72.4%** | Sonnet 5.5 = 83.9% |
| Terminal-Bench 4.0（终端编程） | 0 | **39.2%** | — |
| GDPval-AA（知识工作） | — | **1,620 分**（上代两倍多） | — |
| HLE 不带工具（多学科难题） | 10.2% | **45.9%** | — |
| Artificial Analysis 指数 | — | **43**（最高性能模式） | GLM-5.3 Flash 42 / Gemini 3.8 Flash 41 / GPT-6 Luna 38 |

OSWorld 从 15.7% 冲到 72.4%，离 Sonnet 5.5 只差 11.5 个百分点——上一代 Haiku 在这件事上基本是废的。配合新加的 Browser Use，它第一次有了正经的浏览器操作能力。但复杂编程这一项，官方没把它摆到和 Sonnet 同一条线上，第三方实测的说法也是「差距依然明显」。

## 四、该交 / 别交

判断标准只有一条：**这活是「输入长、输出短、错一次不要紧」，还是「输出长、链条长、错一次很贵」。**

| 该交出去 | 为什么 |
|:---|:---|
| 批量摘要 | 输入长输出短，正好吃最便宜的输入价 |
| 分类打标 | 高频重复、低延迟，官方点名用途 |
| 信息提取 | 输出极短，成本几乎只由输入端决定 |
| 数据整理 / 格式转换 | 规则明确、出错能立刻发现 |
| 客服实时回复、语音助手 | 要的是延迟和吞吐，不是每次答得深 |
| 浏览器操作 | 5.5 才真正具备，上一代做不了 |
| 给主模型当子智能体 | 官方推荐架构 |

| 别交出去 | 为什么 |
|:---|:---|
| 复杂编程 | 与 Sonnet 差距仍明显，省下的 token 钱补不回返工时间 |
| 单次灌超 10 万 token 的长文档 | 单价跳到 5 倍，「一次全丢进去」在这里最贵 |
| 必须一次做对的高风险判断 | 便宜模型的错法是不报错，直接给一个像模像样的错答案 |
| 长链条自主规划的主控 | 规划是 Sonnet / Opus 的活，Haiku 适合执行拆好的步骤 |
| 需要长篇输出的创作 | 输出 $0.50 是输入的 5 倍，写长文成本跑得快 |

这里有个反直觉的账：**「便宜模型 × 返工」不一定比「贵模型 × 一次过」便宜。** 一件活若 Haiku 有三成概率做错、每次纠正要二十分钟，省下的 token 费远不够付时间。判断标准是**单位可交付成果的总成本**，不是单价。

**`effort` 怎么调：** 纯结构化、有标准答案的活（分类、抽取、格式转换）调低；需要判断权衡的活（多步推理、带条件决策）调高。同一任务两种都跑一遍对比正确率再定档——比看任何评测表都准。

## 五、三种接入方式

- **网页端：** 打开 `claude.ai`。Haiku 历来是免费方案也开着的两档之一（另一档是 Sonnet），先试手感不用掏钱。
- **API：** 走 Claude Platform 拿 key，这才是价格表真正生效的地方。批量任务记得加批处理，再打五折。
- **当子智能体：** 让 Sonnet / Opus 负责理解、拆解、检查，把拆出的具体动作交给 Haiku 执行。同一件活主控用贵的、执行用便宜的，总账单明显下来，而且有人检查结果，Haiku 偶尔出错不会漏到最终产物里。

**一条容易漏的额度变化：** 同期开始，Max 和 Team 订阅每月附赠 API 额度——Max 5x 每月 100 美元、Max 20x 每月 200 美元、Team 最多 500 美元全队共用，Claude Platform 上任意模型可用。本来在订 Max 的话，这笔额度正好够把「哪些活该交给 Haiku」实测一遍。

## 六、为什么最后总要回到网络这件事

打开 `claude.ai`、建 key、跑批处理、反复对比两代 token 数——共同前提是**稳定地把页面打开、把请求发出去**。

- **明面一层是能不能开。**
- **隐蔽一层是账号环境前后是否一致。** 平台会拿这次环境和上次比，出口归属、时区、语言、设备特征变化太大就要验证。调用 API 会放大这个问题：反复登录控制台、看用量、改配置，**登录越频繁，环境不一致暴露得越快**。

## 七、开工前自查清单

1. **数一遍真实的输入 token**，拿实际会发的内容数，不用示例文本估。
2. **确认单次请求落在 10 万 token 以内**，超了就是 5 倍单价，该拆段就拆段。
3. **看输出长度占比**——输出型的活留在 Sonnet，输入型的活才搬过来。
4. **同任务两代对比一次**，正确率掉太多就逐批灰度，别一次全搬。
5. **给 API 加上批处理**，五折是白给的。
6. **主控和执行分开**，拆解与检查交给 Sonnet / Opus。
7. **链路先测长任务**，拿一次真实的几万 token 请求压一压，比刷首页有用。

## 八、常见问题

**Q：降 90% 是真的吗？**
单价确实是（10 万 token 以内）。综合降幅官方算的是约 75%，因为新分词器多算 25%–30% token。两个数字都对，说的是不同的东西。

**Q：Haiku 5.5 和 GPT-6 Luna 怎么选？**
10 万 token 以内的输入、输出、缓存价格两家几乎完全一致。差别在长上下文：Luna 要到大约 27 万 token 才涨价，涨完输入也才 $0.20。**长文档场景 Luna 更划算，短请求场景两家打平**，此时按已有生态和工具链选。

**Q：免费用户能用吗？**
能。Haiku 历来是免费方案也开着的两档之一。区别在配额和高阶模型是否可用。

**Q：100 万 token 上下文是不是可以随便灌长文？**
不是。上下文装得下和计费划算，是两件事。超 10 万 token 单价跳 5 倍，整篇灌进去往往比拆成几段更贵。上下文大解决的是「能不能一次看懂」，不是「怎么算钱最省」。

**Q：effort 调低会不会答不准？**
在需要判断的活上会。规律是：有标准答案的活调低几乎无损，需要权衡的活调低掉分明显。拿自己的任务实测一遍再定档。

**Q：该把现有项目整个搬过去吗？**
不建议一次全搬。先挑一类「输入长、输出短、错了能立刻发现」的活做灰度，跑一段对比正确率和账单再决定。复杂编程和长链条规划这两类，暂时留在原模型上。

## 九、总结

**第一，是真降价，但别按 90% 做预算。** 单价降九成、综合降约 75%，中间那 15% 被新分词器吃掉了，做预算按 70%–75% 留余量。

**第二，价值在「跑量」不在「变聪明」。** 操作电脑类任务从 15.7% 到 72.4% 是最实在的进步，配合 Browser Use 和子智能体定位，它补上的是「便宜地做大量小事」这个位置；复杂编程仍与 Sonnet 差一截。

**第三，判断标准是「单位可交付成果的总成本」。** 便宜模型乘上返工未必更省，真正的省钱打法是分工：贵的模型负责理解和检查，Haiku 负责执行，把钱花在它最擅长的输入侧。
