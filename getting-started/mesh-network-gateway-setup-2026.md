# Mesh 组网接旁路由：全屋满格，一走出客厅却开始转圈（2026）

**2026 年 10 月更新。** 上个月帮朋友看一套三居室的网络：客厅一台主路由，主卧和书房各一个 Mesh 节点，手机走到哪儿都是满格。可他一进书房，网页就转圈，iCloud 照片卡在「正在同步」，笔记本终端连 GitHub 直接超时。他以为是信号不够，又买了一个节点——装上去一样。后来把旁路由的电源拔了，三个房间立刻全好了。问题从头到尾都不在信号上。

## 太长不看版

| 问题 | 短答 |
|:---|:---|
| Mesh 管什么 | 只管无线覆盖，不管流量往哪走 |
| 旁路由管什么 | 只管分流与 DNS，不关心无线 |
| 全屋只允许几个 DHCP | 一个。多一个就是「时好时坏」 |
| 全屋允许几层 NAT | 一层。两层会让旁路由对一半设备失效 |
| 拿不准怎么办 | 所有 Mesh 节点切 AP／桥接模式，拨号和分流交给一台设备 |
| Mesh 铺完还要复核什么 | 设备数上限、晚高峰并发、接管方式 |

## 一、信号、路由、分流是三件不同的事

家里网络出问题，多数人只看 WiFi 图标几格。但「能不能上网」这条链上有三层独立的东西：**无线覆盖**（Mesh、AP、信道决定）、**路由层级**（拨号设备与 NAT 层数决定）、**分流策略**（网关、规则、DNS 决定）。

Mesh 只做第一层，它对第二、第三层一无所知；旁路由只做第三层，它甚至不关心无线。两套东西的耦合点，全屋只有两个：**谁拨号、谁发 DHCP**。这两个点定死，剩下都是细节。

一个顺手的判据：直连光猫测速能到运营商承诺的九成以上，说明外线没问题，麻烦在路由器与房间布局这一段；直连也不达标，先找运营商查光衰和光猫配置，别急着换设备。

## 二、三种接法，只有两种是对的

**接法 A：主路由拨号，Mesh 全 AP，旁路由只当网关。** 光猫改桥接（改不了就至少关掉它的 DHCP），主路由 PPPoE 拨号、MTU 写 1492；所有 Mesh 节点切 AP／桥接，有线回程优先；旁路由 LAN 口接主路由 LAN 口，主路由关 DHCP、由旁路由统一发地址；旁路由下发的网关和 DNS 指向它自己，而**它自己的默认网关必须指回主路由**。整个家里只有一个网段、一台 DHCP、一个出口。

**接法 B：软路由当唯一主路由，Mesh 全部 AP。** 把主路由和旁路由合并成一台 x86 双网口小主机，拨号、DHCP、分流全在它身上。最干净的形态，代价是要动弱电箱、要自己刷固件，出问题没有厂商客服可问——[全屋方案怎么选](home-network-setup-guide-2026.md)那篇把四种形态的成本和门槛摆过一张表。

**接法 C：节点保留路由模式（不建议）。** 主路由一层 NAT、节点再一层 NAT，客户端跨节点换了网段，旁路由发出的网关对它不生效。表现是你从客厅走到卧室，国内网站照常打开、境外站点全挂——卧室那台设备的网关根本不是旁路由。

## 三、四个高频错误，一个附赠

**错误一：两台设备同时发 DHCP。** 谁先应答，客户端就用谁给的网关。于是同一个房间，早上拿到旁路由发的地址（分流生效），下午重启一次路由器，拿到主路由发的地址（分流不生效）。你以为线路不稳，其实只是抽签抽输了。改法：只留一台发 DHCP，关之前先改网关再关服务——顺序反了管理页会直接进不去。

**错误二：无线回程，还指望满速。** 今年 9 月知乎上那篇全屋 WiFi 有线 Mesh 的实操写得很直白：无线回程靠节点之间无线传数据，穿墙之后网速腰斩、延迟往上飘；有线回程才是满速无衰减。厂商技术博客讲「为什么加了节点反而更慢」，归因也一致——无线回程、节点摆位、信道重叠。自查不用工具：同一台笔记本在主路由旁边测一次、在节点旁边测一次，只有一半就是回程在拖。三频机型可以把 6GHz 整个让给回程，双频机型没这个余量，老老实实拉一根六类线。

**错误三：漫游切换，把长连接一起切没了。** 从客厅走到卧室，手机换节点那一两秒，TCP 会话是断的。浏览器马上重连你感知不到；但 SSH、WebSocket 行情推送、云盘同步、Agent 长任务，都是「断了得从头来」。9 月有家做跨境线路的服务商在博客里写过这个现象：先看节点与频段，再看客户端在路径变化时有没有重连——**有线正常就说明账号没问题，问题在无线这一段**。能做的三件：开 802.11k/v（有的固件叫「快速漫游」）、2.4G 与 5G 用同一个 SSID、电视和台式机直接走有线。

**错误四：DNS 与 IPv6 的泄漏。** 主路由配了加密 DNS，节点下设备照旧去问运营商。IPv6 更隐蔽：客户端只接管 IPv4 时，AAAA 记录仍从运营商 DNS 出去，境外站点解析结果跟着变。检查不用装软件：在两个不同节点下的设备上各跑一次域名解析，看解析服务器归属是不是同一个。处理办法是网关级统一——旁路由发 DHCP 时把 DNS 一起发下去。IPv6 只分配不接管的细节，[DNS 那篇](dns-pollution-guide-2026.md)有完整配置步骤。

**附赠：旁路由把网关指成了自己。** 改完保存，全家断网，连管理页都进不去。旁路由的角色是「被别的设备当成网关」，它自己的默认网关必须指回主路由。这一条每年都要在群里看到几次，症状和机器烧了几乎一样。

## 四、Mesh 铺完之后，必须复核的三件事

**设备数。** 全屋 Mesh 的家庭，8 到 15 台同时在线是常态——手机、平板、电视、盒子、扫地机、摄像头、门锁网关、打印机。入门档只给 3 到 5 台的，铺完全屋那天就会开始弹「设备数已满」。

**晚高峰并发。** Mesh 只是把信号铺开，链路那一段一寸没变。晚上七点到十一点全家人一起用时，该挤的地方还是会挤，[家庭共享那份横评](family-network-comparison-2026.md)算过这笔账。

**接管方式。** 客户端装在每台设备上只覆盖装了的那几台；网关级接管一次配置全屋生效。Mesh 全屋这种场景，后者省下的时间比省下的钱值钱。[TUN 模式](tun-mode-guide-2026.md)这类细节单独写过，照着开就行。

## 六、上电之前，八条自查

1. 全屋只有一台设备在发 DHCP；
2. 从客户端往上数，NAT 只有一层；
3. 能拉网线的节点就别用无线回程，接受不了半速就先拉线；
4. 2.4G 和 5G 用同一个 SSID，除非要给 IoT 单独隔离；
5. 在至少两个节点下各做一次 DNS 归属检查；
6. 电视、台式机、游戏主机走有线；
7. 全屋设备数对一遍套餐上限，留两台余量；
8. 晚上八点到十点测一次，白天的数字不算数。

## 常见问题

**Q：加了节点反而更慢，是不是坏了？** 多数不是。先看回程是有线还是无线，再看两个节点的信道有没有挤在一起，最后看摆位——隔两堵承重墙的无线回程，等于花钱买了一个减速带。

**Q：主路由和旁路由都开着 DHCP，会怎样？** 设备随机挑一个网关，分流时灵时不灵。这种故障最费时间，因为每次重启都「好像好了」。

**Q：小户型有必要上 Mesh 吗？** 八十平以内一台机器摆对位置就够。买三件套之前先挪一下路由的位置。

**Q：Mesh 节点能不能只当 AP？** 主流套装都支持，设置里叫 AP 模式、桥接模式或者「无线接入点」。切过去之后，拨号和分流只在主设备上做。

**Q：手机在卧室刷视频正常，笔记本却连不上？** 两台设备可能不在同一个网段，或者笔记本走有线、网关指错了。先看它拿到的网关是谁，再看 DNS 是谁。

**Q：全屋十几台设备，套餐要买几台？** 按「同时在线」算，不按「家里有几台」算。手机、电视、盒子、平板加起来通常 6 到 10 台，留两台余量最稳。

**Q：漫游时游戏掉线，能治吗？** 能缓解不能根治。有线接主机、2.4G 留给手机、开快速漫游，三件做完会好很多；彻底不掉线这件事，只有不移动的设备才谈得上。

## 收尾

无线覆盖是把水铺开，分流是决定水往哪儿流。铺得再开，管子也只能有一根——两根管子接在一起，水就不知道该往哪儿走。先把「谁拨号、谁发 DHCP」定下来，再去调信号；顺序反了，你会一直在换设备。
