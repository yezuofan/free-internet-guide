# 光猫改桥接实操：软路由拨号、IPTV 不断、改坏怎么救（2026）

**2026 年 10 月更新。** 上周帮人处理一个特别典型的电话：千兆宽带、光猫拨号，晚上八点一到，三台手机加一台电视一起看视频，网页开始转圈，测速从 900 多掉到 80 兆。他以为宽带缩水，打电话骂运营商。装维上门看了一眼说，线路没问题，光猫 CPU 满了。

出厂默认的**路由模式**下，光猫自己拨号、自己做 NAT、自己发 DHCP、还自己开 WiFi。一台运营商集采的小盒子硬扛全家的连接数，扛不住很正常。想让它退休、把拨号交给软路由，只有一条路——改桥接。

## 一、桥接把什么拆掉了

路由模式的光猫是这条宽带的「大脑」：拿运营商账号 PPPoE 拨号、给每台设备发 192.168.x.x、中间做一层地址转换。桥接模式把这层全拆了，光猫只把光纤里的光信号变成电信号从 LAN 口吐出去，拨号、NAT、DHCP、WiFi 全交给后面那台设备。

光猫这东西的成本结构决定了它干不了重活。运营商集采一台要同时给到千兆口、双频 WiFi、IPTV、电话口，留给 NAT 转发和会话表的内存就那么点。会话表满了之后新连接排队等着，表现出来是所有人都觉得「网慢了」，其实带宽一点没少，只是没人能挤进去。

换来的三样东西：少一层 NAT（端口映射、远程桌面、游戏联机不用再折腾两层转发）、分流规则统一配一次而不是每台设备装一遍、光猫那个可怜的会话表被彻底解放。

代价也要说清楚：光猫配置页从此得想办法才进得去，IPTV 可能要重新配，出问题自己排查，装维上门前最好先还原。

## 二、动手前必须抄下来的 5 个参数

这一步 90% 的翻车都出在这里。删掉原 WAN 之后参数就没了，重建时填错一个（尤其 VLAN ID），光猫注册正常、指示灯全绿、就是上不了网。缺一个都别动手。

1. **宽带账号和密码**。账号一般是手机号或「区号+号码」，密码有的是身份证后 6 位、有的是 123456、有的随机。别猜，翻装机回执，或直接打客服问 PPPoE 密码。
2. **原 WAN 的 VLAN ID 和 802.1p**。进「网络 → 宽带设置」，那条已存在的上网连接里能找到，截图或手抄。
3. **LOID 或设备注册码**。在「网络 → 远程管理 → PON 设置」附近，GPON 靠它认证。没有它，改坏了只能等装维上门。
4. **IPTV 的 VLAN 和组播 VLAN**。看电视走运营商机顶盒的话，光猫里有单独一条 IPTV 连接，值抄下来。
5. **超级管理员账号**。普通账号（useradmin 之类）登录进去看不到 WAN 配置页。超管常见形态是 telecomadmin、CUAdmin、CMCCAdmin；密码有的印在机身贴纸，有的得找装维要。网上流传的默认密码对新型号基本失效。

顺手再做一件：用手机把改之前的每一页配置拍一遍。真要还原，照片比记忆靠谱。

## 三、七步把 WAN 改成桥接

各家界面不一样，天翼网关、联通 HG 系列、移动 GM 系列菜单名都有差别，逻辑是同一套。对不上的地方按「封装类型 + 连接模式 + VLAN」这三个关键词找。

1. **网线直连**：电脑用网线接光猫 LAN1，别用 WiFi 改——改到一半断网只能 reset。
2. **超管登录**：地址通常 192.168.1.1，端口和路径看机身贴纸。
3. **找到那条上网 WAN**：连接模式为 Route 的那条，把 VLAN ID、802.1p、MTU 抄下来。
4. **改它**：能直接改的，把「连接模式」从 Route 改成 Bridge 保存；不给改的，删了重建——封装类型 PPPoE、连接模式 Bridge、IP 模式 IPv4&IPv6，VLAN ID 原样填回。
5. **绑网口**：把要拨号的口（一般 LAN1）绑到桥接 WAN；有 IPTV 的，把机顶盒那个口单独绑到 IPTV 连接，别混在一起。混了电视就看不了。
6. **关掉光猫 WiFi**：桥接后它发不了地址，留着只多一份 2.4G 干扰。
7. **软路由拨号**：WAN 口接光猫 LAN1，协议选 PPPoE，填账号密码。日志里看到 PAP/CHAP authentication success 就稳了。拨不上先回头核对账号密码，别一上来就怀疑硬件。

换完之后还有四五件事要重新确认：DHCP 地址池别跟原来网段撞、DNS 别再指光猫、端口映射全部重做（出口换人了）、UPnP 开不开想清楚、NAS 与摄像头按 MAC 绑定而不是只设静态 IP。漏一件，都会以「某台设备上不了网」的形式找上你。

## 四、MTU 填多少：这一步决定「能打开但卡」

PPPoE 在以太网帧里加 8 字节头，MTU 理论上限是 1492，部分地区实际链路还要低，1480 才稳。症状很好认：网页能开、微信能发，但大文件下载龟速、某些网站转半天打不开、视频一直缓冲——不是速度问题，是包被丢了。WAN 的 MTU 写 1480，把 MSS 钳位（clamp MSS to PMTU）打开，IPv6 那一侧跟着测一遍。细节见[MTU 与分片那篇](mtu-mss-fragmentation-guide-2026.md)。

## 五、两个最容易以为「坏了」的坑

**坑一：再进不去光猫后台。** 桥接后光猫在逻辑上退出了内网路由，管理地址不再有设备帮着转发。三个办法：给软路由加一条指向光猫管理地址的静态路由并让某个 LAN 口能摸到那个网段；把光猫管理地址改成与内网同段并放行；最土的是拔网线、电脑设静态 IP 直连。我一般选第一种，配一次不用再管。

**坑二：运营商把它改回去。** 有的省份开了 TR-069/ACS 远程管理，运维侧定期下发配置，你改的桥接某天被覆盖回路由，表现是家里又变双重 NAT、分流失效、端口映射不通。对策是清空 ACS 地址或关掉远程管理开关，代价是运营商没法远程排障、没法远程下发业务，以后只能等上门。自己权衡，我的选择是关掉，然后把所有参数拍照存档。

## 六、IPTV 怎么保住

桥接只影响「上网」那条连接，IPTV 在光猫里是另一条独立连接、自己一套 VLAN。

**省事的路子**：光猫上保留 IPTV 连接，机顶盒那个口绑到 IPTV，不动。机顶盒照常看，代价是必须用运营商的盒子。

**折腾但更好用**：把 IPTV 的 VLAN 透传到软路由，开 IGMP 代理，用 udpxy 或 msd_lite 把组播转单播。转完家里任何一台设备都能拉直播流，不用机顶盒。

还有一种情况：光猫到客厅只有一根网线，上网和 IPTV 都得走它，这叫单线复用，用 802.1q 在两端打标签把两路塞进一根线，两端都支持 VLAN 才玩得转。

## 七、改坏了怎么救

**有 LOID 就能救，没有就得等人。** 针孔按住 10 秒恢复出厂，光猫回到路由模式但宽带业务是空的；进后台找到 PON 注册页，用 LOID 重新注册，成功一般会自动下发业务配置，重新拨号就通了。

注册失败两种：LOID 抄错了（核对一遍），或光路侧没放开（别再试了，直接打 10000/10010/10086 报「光猫注册不上」）。还有一种更隐蔽的：注册成功、灯全绿、就是上不了网，八成是 VLAN ID 填错了，回去翻照片。

别在晚上动手，改坏了没人半夜给你远程下发。

## 八、桥接之后，加速服务该买哪一档

这一段最容易被忽略。原来的客户端是「一台设备一个出口」，桥接加软路由之后，全屋几十台设备共享一个出口，流量和设备的算法全变了。

**设备数口径**：各家标注的「支持 X 台设备同时使用」多数按授权出口或连接数算，全屋走软路由对外就是一个出口。但确实有服务方按连接设备特征判断，口径不一致。全屋场景下单前问一句客服，比事后扯皮省事。别看着写「3 台」就以为全家只能三台，也别反过来觉得随便挂。

**流量**：一个人刷手机一个月 100GB 够用；全屋过软路由，4K 一集剧约 3 到 5GB，一家三口一个月 300GB 是起点。按单人用量估，第一个月就限速。

## 九、六个常见问题

**桥接之后网速会变快吗？** 不一定。原来光猫是瓶颈会明显改善；原来光猫能跑满、软路由 CPU 又弱，改完反而更慢。软路由 NAT 性能看单核频率，不是核心数。

**光猫的 WiFi 还能用吗？** 不能。它已经没有路由功能、发不了地址。真想留着覆盖，把它当纯 AP 用，但要关掉它的 DHCP，否则两台设备抢着发地址，家里会随机断网。

**能不能只桥接一个口，其他口继续走光猫上网？** 部分型号支持一条路由 WAN 加一条桥接 WAN 并存，网口分开绑；多数家用光猫只给一条上网连接。想这么干先查你型号的论坛帖。

**多拨能叠加带宽吗？** 个别地区允许同账号并发拨号，OpenWrt 上用 mwan3 可叠加；多数地区第二次拨号直接失败或几分钟后被踢。

**改桥接会被运营商发现吗？** 不会，桥接是光猫自带功能，运营商侧看到的就是一个正常 PPPoE 会话。

**改完 IPTV 没了还能救吗？** 能。IPTV 是独立连接，按抄下来的 VLAN 把那条连接绑回机顶盒的口就行，不影响桥接的上网连接。

## 最后

桥接技术上不难，难的是动手前那十分钟的记录。参数抄全了，改坏了二十分钟救回来；少抄一个 VLAN，就得等装维隔天上门，还得解释自己干过什么。

至于改不改，看现在的痛点：只嫌 WiFi 弱，换个好点的路由器当 AP 更省事；连接数一多就掉速、或者非要在软路由上统一做分流，那桥接是绕不过去的那一步。
