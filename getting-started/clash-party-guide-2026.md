## 一、它现在叫什么

改名发生在 **v1.8.6（2025-08-31）**。那版更新说明的功能列表里有两条：「修改软件名称为 Clash Party」「全新设计的 Logo」，同一份说明开头还写了一句「本次更新修改了软件名称，可能导致不可预期的 BUG，请大家积极反馈」——开发方自己知道会出事，后来确实出了，9 月 1 号就有人报告旧版点升级提示 404。

变了什么：

| 项目 | 改名前 | 改名后 |
|:--|:--|:--|
| 软件名 | Mihomo Party | Clash Party |
| GitHub 仓库 | mihomo-party-org/mihomo-party | mihomo-party-org/clash-party |
| 官网 | — | clashparty.org |
| 安装包文件名 | mihomo-party-… | clash-party-… |

没变的：开发组织还叫 `mihomo-party-org`，内核还是 Mihomo（外加一个自家的 Smart 内核），订阅导入方式一个字没改。所以换个名字不等于换个软件。

旧仓库地址还能敲，301 直接跳新仓库。但官网首页那个「下载」按钮，链接到今天还指着老路径，靠跳转才能到——不影响用，说明有些地方没同步干净。

为什么改名，官方说明里没写，代码提交里也没写理由。

## 二、下载：只认两个地方

官方渠道两处：GitHub 仓库 `mihomo-party-org/clash-party` 的 Releases 页，和官网 clashparty.org。别的别碰。

两百兆的包第一次见多半以为下错了。没下错——Electron 外壳加两个内核，体积就是这样。

**坑一：双文件名。** 上面每个包，发布页里都有一个 `mihomo-party-` 开头的副本，字节数完全一样。仓库里的构建脚本 `scripts/copy-legacy-artifacts.mjs` 注释写得很直白：「将 clash-party 重命名为 mihomo-party，用于更新检测兼容性」。所以不是两个版本，是同一份文件复制出来的。也别以为看到 `mihomo-party` 开头就是「老版本还在更新」。

**坑二：聚合下载站。** 客户端经手你全部的订阅链接和流量，从网盘、软件站拿改包版的后果比装盗版播放器严重得多。

## 三、导入订阅：三种链接，只有两种能配它

操作本身很短：左侧「订阅」→ 新建 → 粘贴 → 保存 → 更新。2.0.5 在这块动了两处：订阅支持自定义主页、导入时自动填充订阅信息、还能顺手选代理组。

会卡住的是**你的机场给的是哪种链接**：

1. **Clash / Mihomo 系订阅（YAML）**——直接能吃。
2. **通用 base64 分享链接**——客户端不认格式，得先转。
3. **机场规定只能用自家客户端**——这一类下客户端再顺也没用，根本拿不到能用的订阅。

第 3 类不是理论风险。11 月 21 日把机场名册里的套餐说明逐家翻了一遍，有两家明确写了限制：

- **自由猫**：八个档位，从 ¥8 的 30GB 小仓鼠到 ¥439 的 5TB 不限时包，套餐说明最后都挂一句「仅官方客户端」。
- **大象网络**：套餐里写「自研客户端」。

结论很干脆：**要用 Clash Party，这两家别考虑。** 反过来，已经在用自由猫的人，这篇的意义只剩一个——知道为什么装不上，别再去折腾内核和端口。这条判断有把握，因为它写在套餐条款里，不是听谁说的。

## 四、内核启动出错：四条真原因

先给动作：打开左侧「日志」页，筛选关键字设成 `error` 或 `fatal`，看第一行报什么。别从头读，会被几百行 info 淹没。

**原因一：REALITY 节点的 short-id 没加引号。** 2.0.5 发布说明原文：「修复未加引号的 REALITY short-id 被错误解析为数字的问题」。某些订阅里 short-id 恰好长得像数字，客户端就当数字处理，内核直接起不来。所以排查第一步永远是**先升到 2.0.5**。

**原因二：配置里的日志等级不是 info 也不是 debug。** 2.0.0 修过——生成配置用了别的等级，导致内核启动检测异常，明明跑起来了界面报「启动失败」。手改过 `log-level` 的改回去。

**原因三：Windows 权限链断了。** 2.0.5 在 Windows 上修了一长串：管理员模式重启时授权提示异常、取消授权后应用直接退出、权限检测超时后把错误结果缓存。症状看着不同，根都在权限。先以管理员身份重启一次，别反复点授权。

**原因四：内核残留进程。** 旧版在 Windows 上清理内核时，可能把别的程序甚至别的用户会话里的内核进程一起干掉。表现是刚启动就崩。2.0.5 之后基本没了。

还有一种跟客户端无关：**订阅本身是坏的**。节点过期、机场换域名、链接被重置过——升级客户端换内核都白费，去面板重新复制一条更快。

## 五、手机端：官方没有

v2.0.5 那 89 个文件数过，只有 Windows、macOS、Linux 三套，没有一个 `.apk`，也没有 iOS 包。不放心是「这一版刚好没做」，又翻了 2.0.4、2.0.3 和改名那版 1.8.6——四版加起来 288 个文件，安卓包和 iOS 包一个都没有。

手机上要代理得换客户端：安卓用 CMFA / Surfboard / v2rayNG / NekoBox；iOS 用 Shadowrocket / Stash / Karing，同一个订阅能共用。

**别去搜「Clash Party 手机版」然后从第三方站下 APK。** 这类改包最常见的做法是塞订阅劫持，你粘进去的链接会先过一手别人的服务器。

## 六、「怎么续费」——这个问题问错了

这个软件**不收钱**：GPL-3.0 开源，没有账号、没有会员、没有订阅制，也没有「高级版」。你手上那笔钱从来都是付给机场的。

要续的是机场套餐。2.0.5 在这块只改了一点：订阅到期日期跟着系统区域格式显示。

真正会被坑的地方在机场侧。有的机场续费是**天数叠加、流量覆盖**——账上还剩 10 天 200GB，续一个月 384GB，续完变 40 天 384GB，原来那 200GB 直接没了。别在月中流量还剩一大半的时候顺手点续费。

还有一条：机场换域名后旧订阅链接可能拉不动，表现是「更新订阅失败」，不是客户端坏了。

## 七、跟 Clash Verge Rev 差在哪

两个跑同一个内核（Mihomo），配置互通，同一份订阅粘进去两边节点一样。所以「哪个更快」不太成立——线路快不快取决于机场，不取决于壳子。

Clash Party 的差别在壳上：内置两个内核（Mihomo + 自家 Smart 内核，一键 Smart 规则覆写的官方说法是「基于 AI 模型自动选择最优节点」，我没有测试数据，只能确认这开关存在）；免服务模式的 TUN；深度集成 Sub-Store；覆写功能强；WebDAV 一键备份恢复。

只想导入订阅上网的，两个都行。想把多份订阅合成一份统一配置的，Sub-Store 集成更省事。

## 九、常见问题

**Q：Mihomo Party 和 Clash Party 是同一个软件吗？**

是。2025-08-31 的 v1.8.6 把名字改成 Clash Party，开发组织、代码、内核都延续下来，老仓库地址 301 跳新地址。

**Q：为什么发布页有两套安装包？**

为了兼容老版本的更新检测。构建脚本会把 clash-party 开头的产物复制一份、改名成 mihomo-party 开头一起发。两份字节相同。

**Q：老版本点升级提示 404 怎么办？**

刚改名那阵的问题，v1.8.6 只发了新文件名的包。v1.8.7 之后每个版本都带旧名字副本。还失败就手动下 clash-party 开头的新包装一遍。

**Q：需要付费吗？**

不需要。软件开源免费，没有会员等级。要续的只有机场套餐。

**Q：手机上能装吗？**

官方没有手机版，只覆盖 Windows / macOS / Linux。安卓用 CMFA / Surfboard / v2rayNG，iOS 用 Shadowrocket / Stash / Karing。
