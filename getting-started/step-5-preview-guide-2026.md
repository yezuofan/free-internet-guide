## 一、为什么要单独看这一款

9 月这条时间线：9/2 Gemini 3.8 Flash 与 Qwen3.8-Max-0902 同日，9/10 DeepSeek V4.1 Flash，9/15 智象 HD-V1，9/17 中国电信星辰 Xing4.0，9/20 轮到阶跃 Step 5 Preview。一个月五家上新，单个模型要被记住，得有一个别人没占的位置。

Step 5 Preview 占的位置是「效率」。最反直觉的一点：阶跃上一代旗舰是万亿参数，这一代反而缩到 600B。官方解释是路线调整——从继续堆算力转向提高算力转化为智能的效率，每代都在压「完成一件事的总成本」。

据每日经济新闻与新京报报道，这款模型面向 AI 编程、软件工程、专业知识工作与金融四类场景，覆盖「长上下文、多轮工具调用、持续执行」的真实工作量。**这三个词描述的不是聊天，是一个 Agent 在工作台上连续干活的样子。**

## 二、92 层「窄而深」是什么思路

| 项目 | 规格 |
|:---|:---|
| 架构 | 稀疏 MoE，92 层「窄而深」+ 稀疏注意力 |
| 总参数 / 激活 | 600B / 27B（每次推理约 4.5%） |
| 上下文 / 最大输出 | 100 万 Token / 64k Token |
| 输入模态 | 文本 + 视觉，原生支持 |
| 输出速度 | 约 100 Token/秒 |
| 权重开源 | 2026 年 10 月 15 日 |

稀疏 MoE 的道理不复杂：模型存着 600B 的知识容量，每生成一个 Token 只叫起相关的那几个专家，实际参与计算按 27B 算。**存储按 600B，推理成本按 27B，这是价格能压下来的物理基础。**

「窄而深」是另一个取舍：层数堆到 92 层、每层收窄，配合稀疏注意力，针对的是长上下文下的注意力开销。1M Token 上下文配 64k 最大输出，能落地的场景是几份上百页的招股书、整个代码仓库、一整套会议记录一口气丢进去，直接要结构化结果——过去「切片 + 检索 + 拼答案」的三段流程，可以退化成一次调用。

## 三、44 分站在什么位置

第三方看 Artificial Analysis 的 Intelligence Index，Step 5 Preview 拿到 **44 分**。口径上有个差异：官方说「全球开源模型前三」，部分媒体写「前二」，两个说法来自同一批榜单数据，只是对并列与版本口径的处理不同。排在它前面的开源模型是 Qwen3.8 Max（0902）与 GLM-5.3（max）；这一档上它与 2.8 万亿参数的 Kimi K3 持平，比 GLM-5.3、Claude Opus 5 各低一分左右。

**更该盯的是拿到这 44 分要花多少钱。** 按 Artificial Analysis 数据，它完成榜单任务的平均单次总开销是 0.71 美元（约 4.76 元），Claude Opus 5（max）是 5.86 美元（约 39.25 元），差 8 倍多，对上官方那句「单任务成本约为 Opus 5 的八分之一」。

专项成绩：StepCodeBench 49.0%（自建评测，553 个代码仓库、33 种编程语言）、DeepSWE v1.1 67.7%、ProgramBench 80.5%；输出速度约 100 Token/秒，AA 榜第 6。在 Agent 长周期 CLI 任务、金融投资研究（FrontierFinance）、跨领域深度研究（DRACO）上，多家媒体引用官方数据称它优于 Kimi K3 与 GLM-5.3，略逊于 GPT-6 Astra 或 Opus 5。**它不是全面碾压型选手，是同档能力里最便宜的那个。**

## 四、价格表与「单任务成本」这笔账

| 计费项 | 价格 |
|:---|:---|
| 输入（缓存未命中） | 7 元 / 百万 Token |
| 输入（缓存命中） | 0.35 元 / 百万 Token |
| 输出 | 20 元 / 百万 Token |

中文媒体折算的美元口径是每百万输入 1 美元、输出 2.7 美元，价位大致对标 DeepSeek-V4-Pro 高峰时段。

关键理解在「单任务成本」和「单次调用价格」的区别：一次调用便宜不等于完成任务便宜，一个便宜但要重试十次的模型，总账可能比一个贵但一次跑通的更烧钱。它在 AA 测试任务里平均生成约 6.4 万个输出 Token、加权平均解码时间约 12.1 分钟——设计目标是十几分钟到几小时这个量级上持续推进任务，**你付的是「任务办成的概率」，不是回答次数。**

再看缓存命中价：0.35 元对 7 元，差 20 倍。这个结构就是冲着 Agent 来的——多轮工具调用里系统提示、任务背景、代码上下文反复出现在每轮请求里，缓存命中比例越高，长链路任务的成本曲线越平。工作流如果是「同一个代码库来回问二十轮」的形态，这个价格结构比绝对单价重要。

## 五、实测三个任务

**1. 纯代码生成一个可玩的 3D 网页游戏。** 没调 Blender、没用现成 3D 素材，全部靠代码生成岛屿、树木、房屋与灯塔，首次交付就是能跑的 WebGL 框架，支持旋转缩放、时间天气切换、建筑放置。这条最能说明「长链路不跑偏」意味着什么——很多模型的翻车方式不是写不出来，而是改着改着把前面能跑的东西改坏了。

**2. 独立做完一个 Chrome 扩展。** 正文提取、长文分段、流式摘要、原文问答、引用定位、历史记录到模型设置，配套产出 Manifest V3 配置、Service Worker 脚本、安装包、应用商店素材、隐私政策，13 项单元测试全过。它还把「上架需要什么材料」一起列了——顺手把周边做完，是判断模型有没有理解任务目标的信号。

**3. 做一份英伟达投资分析。** 从 SEC 文件、财报、电话会记录提取数据，搭出历史财务、收入预测、DCF 与相对估值模型链，输出两份 Excel、一份备忘录和证据清单，关键数字标了来源，主动列出数据冲突与假设，加权目标价 263.06 美元、较基准高 18.4%。人工核查时发现个别公式错误——研究类产出可以当草稿，公式和数字必须自己过一遍。

两个极限实验被反复引用：连续 24 小时自主优化 H100 GPU 内核，约 22 小时后达到 508 TFLOPS（同实验 Opus 5 为 493 TFLOPS）；自己设计后训练数据把 Qwen3-30B-A3B 在 AIME24 上从 53.3% 提到 60%。这些数据的价值不在跑分，在于验证长周期任务里「失败十几次还能接着推进」比「单步做得漂亮」稀缺得多——官方演示里模型连续失败十余次没有崩、没有摆烂，而是一次次调整策略继续走。

## 六、三条接入路径

- 模型名、基础地址与鉴权**以控制台文档为准**，新模型上线初期字段常调整，照抄第三方教程容易踩坑；

## 七、什么时候不该用它

**视觉素材丰富度要求高的产出。** 实测指出的短板很具体：对视觉设计要求复杂的场景，产出形式缺少多元化素材，需要用户介入迭代指令。它的强项是把复杂任务拆开、分步执行、输出可用结果，不是把画面做漂亮。

**只问一句话的轻量场景。** 600B 的知识容量配 27B 的推理开销，回答「今天天气怎么样」这种问题完全是浪费。

**任务拆不清、验收标准说不明白的活。** 测试集成绩漂亮有个前提：任务边界明确。你自己都不知道要什么的时候，它只能给一份看起来完整、实际跑不通的东西。

## 八、长链路 Agent 的隐形成本，一半在网络

这类模型的卖点是「连续干几个小时的活」，但真实工作里很少被讨论的是：**长链路任务对网络质量的要求，比日常对话高不止一个档。** 原因不在模型，在于它的工作方式——每一步之间要接上，就意味着全程要保持持续稳定的外部连接。

四类具体情况：

- **拉代码和依赖。** Agent 做软件工程任务，第一步是把仓库拉下来、依赖装上。GitHub 与包管理源的跨境访问一抖，克隆中断、依赖装一半失败，任务链断在这里。最烦的是它会消耗已经烧掉的上下文，重来一遍 token 钱白花。
- **对外接口的对照测试。** 做选型或效果验证时常要同一份输入跑几个模型对照，海外接口对链路稳定性更敏感，长任务中间超时，前面的推理结果就废了。
- **权重下载。** 10 月 15 日完整权重开源后，自建或本地部署要先拉权重，这类文件动辄几十上百 GB，对下行带宽与断点续传的稳定性要求极高。
- **云端开发环境。** 远端开发机、云端 GPU 一旦抖动，终端会话掉线、长任务被 kill，前面跑的几十分钟就这么没了。

还有一个容易忽略的点：**长任务的出口 IP 最好保持固定。** 中途切换出口可能触发平台侧风控校验导致会话失效，表面上看像模型故障，现场排查非常费时间。

几条实操建议：客户端工具和 CLI 记得开 TUN 模式（命令行程序、模型 SDK、包管理器大多不读系统代理，不开等于没走线路）；长任务开始前先测链路稳定性，看丢包率和抖动而不是峰值带宽；准备一条备用链路；大文件下载单独安排时段，别和实时任务抢带宽。

## 九、常见问题

**1. 免费吗？** 模型不是免费产品，但当前额度宽松：登录即得 15 天，首次 API 调用再 15 天，邀请叠加，最长 75 天，具体名额与条款以官方活动页为准。

**2. 和 DeepSeek、Kimi、GLM 比怎么样？** AA 44 分与 Kimi K3 持平，稍低于 GLM-5.3。DeepSeek 在长文本成本上有优势，Kimi 走长上下文与产品体验，GLM 在中文办公场景沉淀更深。它的差异化是「同档能力里单任务成本最低」，且冲着长链路 Agent 设计。

**3. 100 万 Token 上下文能用满吗？** 技术上限是 100 万，实际有效长度取决于任务形态与接入方式。经验做法是控制在够用的范围，塞进去的无关内容越多，抓重点越不准。

**4. 10 月 15 日开源后能本地跑吗？** 600B 总参数即使稀疏激活部署门槛也不低，个人本地跑基本不现实，更现实的是自有服务器或云上私有部署，普通用户继续走 API 更划算。

**5. 输出能直接用吗？** 分场景。代码、文档、结构化结果可用度较高（13 项单测全过、首次交付即可运行是真实发生的）；研究结论类必须人工复核，实测出现过个别公式错误。把它当高效执行者，不要当最终责任人。

**6. 在国内用它有障碍吗？** 阶跃星辰是国内厂商，Studio 和 API 都在国内，注册调用没有额外门槛。要准备的是工作流里跨境那一环——拉仓库、装依赖、对照海外模型、下载海外权重，这些跟用哪家模型没关系，是你自己的工作环境问题。

## 十、总结

三条对使用者的直接影响：

- 选型别只看跑分，把「完成一个任务的总开销」列进对比维度，尤其是跑多轮工具调用的场景；
- 长任务稳定性（失败了还能不能接着干）比单步质量更值得关注，这类能力演示里不显眼，真实工作里最值钱；
- 缓存命中价与长上下文能力决定了工作流该设计成什么形状——同一个任务反复问二十轮，成本结构完全不同了。

至于网络那一段，说到底是件朴素的事：**模型能把活连续干几个小时的前提，是你的链路在几个小时里不出岔子。** 推理成本已经算得很细了，别让一条不稳的链路把省下来的钱和已经烧掉的上下文一起赔进去。
