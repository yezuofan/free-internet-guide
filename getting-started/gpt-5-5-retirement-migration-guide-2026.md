# GPT-5.5 要在 10 月 14 日下线了：全套餐清退、不做保留通道，迁移到哪、怎么迁

**2026 年 10 月更新。** OpenAI 已官宣：**2026 年 10 月 14 日起，GPT-5.5 从 ChatGPT、ChatGPT Work 和 Codex 全部套餐中彻底下线**，免费版、付费订阅、企业版、编程底座一个都不留，也没有任何 Legacy 保留通道。

这不是"停止更新"，是"移除"——差别很大：停止更新意味着还能调用、可以慢慢迁；移除意味着接口那一端不再接受这个模型名，今天跑得通的请求，10 月 14 日之后直接失败。官方给出的方向是迁往 **GPT-5.6 Sol** 或 **GPT-6 Astra**。

## 一、时间线与覆盖范围

| 日期 | 事件 |
|:---|:---|
| 2026-04 | GPT-5.5 上线，主打省 token、响应快、能扛复杂工作 |
| 2026-06-26 | GPT-5.6 系列发布，拆成 Sol / Terra / Luna 三档 |
| 2026-07-23 | 关停 gpt-5-codex 等 11 个模型快照，旧的 codex 专用模型被并入 5.5 |
| 2026-09-03 | GPT-6 Astra 发布，定位家族最强 |
| 2026-09-22 | GPT-6 Sol 与 GPT-6 Luna 发布 |
| 2026-09-28 | GPT-6.1 Astra 原定 10 月的发布因安全测试未达标取消 |
| **2026-10-14** | **GPT-5.5 全套餐下线** |

受影响入口：ChatGPT 免费版、Plus 等付费订阅、ChatGPT Work 企业版、Codex 编程底座，全部在内；网页端未结束的长对话、后台挂载该模型的 Agent 流水线会在到点时静默中断。

**为什么是清退而不是自然过渡。** 业内的解释是产品矩阵向两端分化：一头是轻量日常生产力，一头是硬核攻坚，夹在中间的 5.5 两头都不占，从"性价比主力"变成了"算力负债"。不管厂商怎么说，开发者要面对的现实是：从上线到下线的间隔不到半年，模型选型已经从"选一次用三年"变成"必须假设半年后会换"。

## 二、谁受影响最大

**纯聊天用户：几乎无感。** 到期后换一个模型继续用。唯一要留意的是输出风格会变——如果你为 5.5 调教过一套固定格式的提示词，新模型不会照样听，重写提示词比抱怨模型退化有用。

**深度集成的开发者和团队：最痛。** 风险集中在三条，且都不是"报错"型的：

1. **提示词漂移。** 同一段 prompt 在新模型上理解不同。最典型的不是答错，而是输出格式变了，下游用正则解析的地方直接崩。
2. **降级逻辑失效。** 很多 Agent 设计了"主模型失败切备用"的链路，如果备用写的还是旧模型名，到点后这条链会在第一次需要兜底时直接失败——**兜底机制本身成了新故障点**。
3. **行为回归。** 输出长度、语气、拒绝边界都可能不同，跑量业务里会被放大成成本和控制问题。

**企业侧：** 麻烦不在迁移动作，在于迁移要通过验证，且该看的不是单价、是**单位任务成本**——更强的模型一次做对，和便宜模型反复重试三次，哪笔账划算得实测。

## 三、迁到哪去：两个家族，结构一样

| 家族 | 旗舰 | 均衡 | 轻量高频 |
|:---|:---|:---|:---|
| GPT-5.6 | Sol | Terra | Luna |
| GPT-6 | Astra | Sol | Luna |

> 注意命名重叠：GPT-6 家族的 **Sol** 和 GPT-5.6 家族的 **Sol** 不是同一个东西，写配置时看清前缀。

| 你的任务 | 建议落点 |
|:---|:---|
| 跨文件重构、长周期 Agent、安全审计、科研级推导 | GPT-6 Astra，或 GPT-5.6 Sol |
| 日常开发、写作、分析、中小型调试 | GPT-5.6 Terra，或 GPT-6 Sol |
| 批量分类、内容初筛、客服对话、高频改写 | GPT-5.6 Luna，或 GPT-6 Luna |
| 只想省钱、任务本身简单 | Luna 档，别上旗舰 |

**迁移不等于涨价。** 按官方口径，GPT-6 Sol 与 Luna 的 API 价格比 GPT-5.6 对应型号的促销价还低约一半，纯 API 调用单位成本可能反而下降。真正会涨的是原先靠 5.5 高性价比干重活的场景——换成 Luna 扛不住，只能上 Sol 甚至 Astra。

**别等 GPT-6.1 Astra。** 它原计划 10 月推出，9 月 28 日因安全测试未达标被取消，问题集中在更高的欺骗行为倾向、以及未经许可调用外部工具或服务的授权范围问题，官方用同一基础模型做强化学习，可能还会来，但没有日期。正确顺序是：10 月 14 日之前先把 5.6 Sol 或 6 Astra 接通验证完，等 6.1 真发布再评估。

## 四、Codex CLI 迁移：三条最容易踩的坑

### 坑一：`model` 字段必须写完整后缀

```json
{
  "model": "gpt-5.6-sol"
}
```

以下三种写法都是错的：`gpt-5.5`（旧值，到时不再存在）；`gpt-5.6`（少了子型号后缀，Sol/Terra/Luna 是同系列下的不同子模型，光写主版本号解析不到）；带空格、大小写不一致、中划线写成下划线的手滑。

### 坑二：写错不报错，它会静默回退

Codex CLI 在模型解析上有一层容错：模型名无法精确匹配到已注册标识时，**不抛错中断，而是回退到内置默认模型**，让会话继续跑。初衷是避免拼写错误导致完全不可用，副作用是迁移场景极难发现——你改完配置、看到会话照常返回，很容易以为切换成功，实际可能还在走旧模型，或走的是内置默认模型（该上旗舰的任务其实跑在轻量档上）。

**怎么确认真的切过去了：**

1. **对照实验。** 把配置改成一个确定不存在的模型名（如 `gpt-nonexistent-test`）跑一次。如果照样返回结果，说明回退机制确实存在，那你之前那次"改成功了"就要多打一个问号。
2. **看用量口径。** 模型调用分布、计费分类比对话内容更能说明实际走了哪个模型。
3. **固定用例回归。** 用一段最熟的代码重构任务当基准，迁移前后各跑一次比对。

### 坑三：降级链和硬编码的模型名要一起改

模型名通常会散落在四个地方，迁移时最容易漏掉后三个：

| 位置 | 典型表现 |
|:---|:---|
| 配置文件 | `config.json` / settings 里的 `model` 字段 |
| 环境变量 | 容器、CI、部署脚本里注入的模型名 |
| prompt 与系统消息 | 模板里写死的旧模型名 |
| 代码与工作流定义 | Agent 的降级链、重试策略、任务路由表 |

排查动作很朴素：

```bash
grep -rn "gpt-5\.5" --include="*.json" --include="*.yaml" --include="*.yml" \
  --include="*.py" --include="*.js" --include="*.ts" --include="*.md" .
```

搜出来每一处都要判断：是历史记录（可以留），还是运行时真正会读到的值（必须改）？**尤其检查降级链**——`fallback` 或 `retry` 里如果还写着旧模型名，10 月 14 日之后这条链会在第一次需要兜底时直接失败，原本的"保险"变成了"引信"。

长期建议：**把模型名收敛成一个配置项或环境变量，别在代码里硬编码。**

## 五、迁移自查清单

| # | 动作 | 目的 |
|:-:|:---|:---|
| 1 | 全文搜索 `gpt-5.5`（配置、环境变量、prompt、CI） | 找全所有写死的地方 |
| 2 | 换成完整后缀的模型名写法 | 避免解析不到 |
| 3 | 检查降级链 / 重试链里的兜底模型是否存在 | 别让保险变引信 |
| 4 | 用固定用例跑回归，重点看输出格式 | 下游解析最容易挂 |
| 5 | 核对计费口径（单价、缓存命中、批量折扣） | 确认成本变化方向 |
| 6 | 长对话与后台任务主动收尾或提前迁走 | 别等到点静默中断 |
| 7 | 把模型名抽成配置项，留切换开关 | 应对下一次换代 |

第 6 条单独说：**长对话和后台任务最容易漏**，因为它不是"报错"，是"静默失效"——网页端开着没结束的长对话、后台跑着挂载旧模型的流水线，时间一到资源供应立刻中断，没有人给你发通知。

## 六、几个连带问题

**成本方向不一致。** 纯 API 调用可能降，靠性价比干重活可能涨。企业该做的是重算单位任务成本，不是盯单价。

**"月抛时代"怎么少被折腾。** 能做三件事：模型名当配置项（换的时候改一处不是改十处）；把对模型的隐含假设写下来（比如"这个流程依赖稳定输出 JSON"，下次换代时就是回归测试重点）；回归用例自动化（哪怕只有五条固定输入输出对，也能十分钟判断迁移行不行）。

**别把"模型变了"误判成"网络坏了"。** 迁移期最典型的误判是顺序反了：输出变差 → 怀疑网络 → 折腾半天代理 → 最后发现是模型落点不对。正确顺序是先确认请求实际打到哪个模型（用量口径），再去看链路——模型落点是配置问题，一分钟能查。

## 七、为什么这类事最后都会撞上网络

上面所有动作——重新验证模型、跑回归、看用量、在 Codex 里反复切配置——都有一个前提：**你得能稳定地把请求发出去。**

对国内用户来说卡点通常是两层：**明面一层是能不能稳定访问**；**隐蔽一层是登录环境前后是否一致**——平台会拿这次的环境跟上一次比，出口归属、时区、语言、设备特征变化大就要验证。迁移期这个问题会被放大，因为你正频繁在多个入口之间切换、反复登录、反复改配置，**反复验证轻则限流，重则封号。**

Codex CLI 有几个报错特别容易让人走错方向：`local proxy failed`、`401 Unauthorized`、读取 choices 失败这类，看起来像模型问题，实际多半出在本地网络环境或凭证通道上。**在花两小时检查模型配置之前，先用一条确定能跑通的通道把请求打通**——顺序反了会白折腾一晚上。

另一个细节：Agent 任务往往是长连接，跨文件重构、批量分析一跑几十分钟，链路中途抖一下，前面跑完的部分可能白费。**这种场景下稳定性比峰值速度重要得多。**

## 八、常见问题

**Q：GPT-5.5 是"还能用但会变慢"吗？**
不是。10 月 14 日起它从服务列表中移除，官方没有保留通道，属于到期清退，按不可用来准备。

**Q：我平时只用 ChatGPT 聊天，需要做什么？**
几乎不用动。到期后在模型选择器里换一个继续用。值得做的只有一件：把常用提示词在新模型上重跑一遍，输出格式变了当场改掉。

**Q：迁到 GPT-5.6 还是直接上 GPT-6？**
看任务和预算。日常主力用 GPT-5.6 Terra 或 GPT-6 Sol，硬活（跨文件重构、长周期 Agent、安全审计）再上 GPT-6 Astra 或 GPT-5.6 Sol，高频批量交给 Luna 档。

**Q：官方有没有可能延期？**
公告里没有任何缓冲期安排，建议按不延期准备。真要延期，你只是提前做完了，没有损失；赌它延期而没做，代价是业务断档。

**Q：我的 Agent 没报错，但结果明显变差了？**
第一怀疑对象是**静默回退**（模型名没解析到，请求被路由到默认模型），第二是提示词漂移。

**Q：国内用 Codex CLI 老报错或者断，是模型的问题吗？**
大概率不是。先分清是链路问题还是账号环境问题，最后才怀疑模型配置。

## 九、总结

**第一，这是一次清退，不是一次过渡。** 10 月 14 日之后 GPT-5.5 不可调用，没有遗留通道，别指望灰度缓冲。

**第二，迁移最难的不是换模型，是发现"没换成"。** Codex CLI 解析不到模型名时会静默回退，会话照常返回、日志未必报错——用固定用例回归、看用量口径，比看"能不能跑通"可靠得多。

**第三，模型名写成配置项，是这轮折腾唯一能留下的资产。** 半年一换代的节奏不会慢下来，这次手工改二十处，下次还得改二十处；收敛成一处，下次就是一行。
