# NAT 类型怎么看：四种类型对照，对称型为什么让做种和联机卡死（2026）

**2026 年 10 月。** 我第一台 NAS 上线那年，PT 站挂了一整晚，第二天早上一看：上传量 0.00 KB，下载倒是跑完了。种子没死，站点没封我，端口也开了。问题不在我做错什么，在我做不了什么——我家那条宽带的外网地址是 `100.64.x.x`，这个地址从头到尾就没在公网上出现过。

同一件事会在很多地方冒脸：Switch 联机测试报 NAT 类型 D，跟朋友连不上；远程串流提示"无法穿透"；家里摄像头外网永远转圈；下载软件连接数始终为零。症状各管各的，底下的原因只有一个：**你的网络在别人眼里"进不来"**。

## 太长不看版

| 症状 | 大概率是什么 | 能不能自己解决 |
|:---|:---|:---|
| 做种上传永远是 0，下载却正常 | 入站连不通：没公网 IP，或映射没生效 | 看运营商给不给公网 IP，改桥接后做映射 |
| Switch 联机报 NAT 类型 D / F | 出口严格型，只能主动连别人 | 改路由器映射，或用对 UDP 友好的出口 |
| PS/Xbox 显示"类型 3""严格" | 同上，家庭网络多了一层限制 | 先排查双 NAT，再做端口转发 |
| 远程串流、监控常失败但网速正常 | 速度没问题，回程路径建不起来 | NAT 类型 + UDP 转发两个方向都要查 |
| 换手机热点就好了 | 那条路径限制更松 | 反证问题在本级网络 |

一句话：**NAT 类型管的是"外面能不能主动找到你"，跟带宽、测速、ping 值都不是一回事。**

## 一、NAT 在干什么：门口那本登记簿

家里的手机、电视、NAS 拿到的都是 `192.168.x.x` 这类内网地址，扔到公网没人认识。所以每次上网，路由器都要做一件事：把内网地址加端口，换成宽带的外网地址加一个它分配的端口，再在登记簿上写一行"内网 A:5000 对应外网 X:31000"。回包照着登记簿翻回去。

这行登记就是 NAT 会话。**关键在于登记簿怎么写、留多久、认不认"不请自来"的包**——这四件事的不同组合，就是你听到的那四种 NAT 类型。

它不是"能不能上网"的开关，默认全开，上网毫无障碍。它影响的是**外部主动发起的连接能不能穿过这层**。浏览器访问网站是你主动出门，永远没问题；别人想连你，得先过登记簿这关。

## 二、四种类型：门卫的四种性格

这套分法出自很早的 STUN 规范（RFC 3489）。现在 IETF 换了描述方式（RFC 4787 把"映射行为"和"过滤行为"分开讲），但设备厂商、游戏机、下载工具都还在用老的四分类。

| 类型 | 映射规则 | 过滤规则 | 典型表现 |
|:---|:---|:---|:---|
| **全锥形** Full Cone | 内网同一端口，外网永远同一个端口 | 谁都放行 | P2P 最好用，等于有固定门牌 |
| **受限锥形** Restricted | 同上 | 只放行你之前主动连过的 **IP** | 大部分场景够用 |
| **端口受限** Port Restricted | 同上 | 只放行连过的 **IP + 端口** | 联机开始挑人 |
| **对称型** Symmetric | **每连一个新目标就换一个新外网端口** | 只放行那条精确的五元组 | 做种、联机、穿透的重灾区 |

拿门卫打比方更快：全锥形是"我家门开着，谁找我都行"；受限锥形是"得是我先打过招呼的人"；端口受限是"还得从我先打过招呼的那个门进来"；对称型最狠——**你每去一个新地方，门牌号就换一次**，别人根本不知道去哪找你。

真正致命的组合只有一个：**对称型 遇上 对称型**。你换门牌，他也换门牌，两边都找不到对方，只能靠服务器中继。联机报"严格"、P2P 连不上，八成是这种局面。

对称型并不"坏"，它是运营商省钱和保护用户的做法，家用宽带做点对点传输本来就不是它的设计用途。只是当你确实需要入站连接时，它就成了硬墙。

## 三、为什么你家大概率是对称型

三层叠加，比例高得吓人。

**第一层，运营商级 NAT（CGNAT）。** 公网 IPv4 早分完了，运营商在小区级网关上再做一层 NAT，几十上百户共用一个公网 IP。打开路由器看 WAN 口地址，落在 `100.64.0.0/10` 段里（比如 `100.72.x.x`），基本可以确定：你根本没有公网 IP，端口映射做在路由器上也没用，因为要进来的包走不到你这台设备。移动宽带尤其常见。

**第二层，光猫的路由模式。** 光猫自己拨号自己做 NAT，路由器再 NAT 一次，就是双 NAT。两层登记簿两层门卫，映射要在两台设备上各做一遍。

**第三层，路由器默认的对称行为。** 很多家用型号为了省会话表，映射策略本身偏保守，天然落在端口受限或对称型。

## 四、三种检测方法

前提一句：**检测必须在你想用的那个网络出口上做。** 挂着客户端测出来是客户端的出口，关掉测出来是家里的出口，是两件事。

**方法一，看 WAN 口地址（30 秒）。** 登录路由器找 WAN / 互联网状态。落在 `100.64.0.0/10` → 运营商级 NAT，后面不用测了；落在 `10.x` / `172.16~31.x` / `192.168.x` → 你家已是多层内网，先解决双 NAT；拿到正常公网地址且与浏览器查到的公网 IP 一致 → 有公网 IP，进下一步。这一步能筛掉一大半人。

**方法二，游戏机自带测试。** Switch 走「设置 → 互联网 → 连接测试」，结果里有 NAT 类型 A 到 F。A 是点对点最理想，F 是完全无法完成点对点；A、B 两档联机基本顺畅，C、D 开始挑人（D 只能和 A 档互通）。PS 显示类型 1/2/3，Xbox 显示开放/中等/严格，三家叫法不同，本质同一套东西换算过来。

**方法三，通用工具。** Windows / macOS 用开源的 **NatTypeTester**（GitHub 上 HMBSbige 那个项目），填 STUN 服务器点测试，按 RFC 3489 / 5389 / 5780 跑一遍，输出 OpenInternet / FullCone / RestrictedCone / PortRestrictedCone / Symmetric，另有一种 `UdpBlocked`。Linux 上 `apt` 或 `dnf` 里搜 `stun` 能找到 `stunclient`，配 `--mode fulltest`；懒得装包可以用 `pystun3`。

**看到 `UdpBlocked` 要特别注意**：这不是 NAT 严格，是 UDP 根本出不去或回不来。挂着某些出口线路时很常见——协议本身不转发 UDP，或者上游把 UDP 掐了。这时候测 NAT 类型没意义，因为整条 UDP 路都不通。

### 检测时最容易错的四件事

**在错的出口上测**：一边连 WiFi 一边挂客户端，结果当然天差地别。**只看结论不看映射端口**：两次探测的映射端口一样就是锥形，变了就是对称型，这条比工具给的名字更可靠。**以为换 DNS 能改 NAT 类型**：不能，DNS 管名字解析，NAT 管地址端口改写，两个层。**只测一次**：会话有老化时间，路由器负载高时策略也可能变，测三次两次一致再下结论。

## 五、能改的和改不了的

按投入产出排。

1. **要公网 IP（免费）**：打运营商客服，明说"我需要公网 IPv4 做端口映射和远程访问"。有的地区一句就给，有的要登记用途，有的直接说没有。
2. **光猫改桥接**：让光猫只做光电转换，拨号交给路由器，少一层 NAT。细节（TR-069 会不会把配置改回去、IPTV 口怎么留）另见[光猫改桥接的坑](https://huanghaiwan.com/posts/fiber-modem-bridge-mode-guide-2026/)。
3. **路由器上做映射**：开 UPnP / NAT-PMP 让软件自己申请（省事，但任何程序都能开洞）；或手动端口转发指到固定内网地址。做种要后者，因为需要**稳定的**入站端口。
4. **上 IPv6**：地址够用，理论上每个设备一个公网地址、没有 NAT 那层，很多人换完做种突然能连上。但运营商侧和路由器的 IPv6 防火墙默认都拦入站，仍要放行端口；开了反而更慢的情况也不少见，取舍见 [IPv6 设置指南](https://huanghaiwan.com/posts/ipv6-settings-guide-2026/)。
5. **换路径**：换运营商不现实，就用中继（Tailscale、ZeroTier 这类）绕开，或把需要入站的服务放到有公网 IP 的地方。

## 六、挂上跨境线路之后，这一层归谁管

挂上跨境服务商之后，流量出口变成人家的机房，**NAT 类型不再由你家路由器决定，而由出口那台设备的映射策略决定**。你在路由器上做的端口映射对这条链路基本没意义——包从隧道出去以后，走进的是人家的登记簿。

三个现实约束：

**出口 IP 是共享的。** 一个出口地址后面挂着很多用户，不可能给每人开独立端口映射，端口表会炸。所以绝大多数服务不承诺 Full Cone 出口，也不接"给我开个映射"这类需求。真需要，先问客服——能明确回答这个问题的服务商，通常对自己架构比较清楚。

**协议决定 UDP 能不能过。** 有些配置只转发 TCP，UDP 直接扔掉。表现是网页、视频、下载都正常，游戏联机、语音通话、P2P 全废，工具一测报 `UdpBlocked`。这跟出口严格不严格是两回事。需要联机的人，选之前问一句"支持 UDP 转发吗"，比看任何测速图都有用。

**换节点就等于换门卫。** 有的节点走中转、有的走专线直出，出口设备不同映射策略也不同，所以同一个账号在不同节点上测出来的类型完全可能不一样——三个节点测出两个对称型、一个端口受限，这种情况并不稀奇。所以"这家服务商 NAT 友好不友好"这个说法本身不成立，得具体到节点。

自己验证的流程：关掉客户端测一次记下来，挂上之后同一个工具再测一次，然后换 2 个节点各测一次。四组数据摆一起，就知道这条链路到底给不给你入站。

## 七、要不要为这件事换服务商

**除非需求明确需要入站连接，否则 NAT 类型不该成为选线路的主要标准。** 刷网页、看流媒体、用 AI 工具、跑下载，全是主动出站，出口严格不严格毫无影响。测速跑得动、晚高峰不掉线才是日常体验的关键——那属于带宽和拥塞控制的事，见[带宽跑不满的原因](https://huanghaiwan.com/posts/tcp-congestion-bandwidth-guide-2026/)和[包大小的问题](https://huanghaiwan.com/posts/mtu-mss-fragmentation-guide-2026/)。

真需要入站的是这几类人：PT 玩家、主机联机（尤其 Switch 的 P2P 匹配）、远程串流和监控、自建服务的开发者。这四类人的正确做法是先看本地能不能拿到公网 IP，那才是根治；服务商出口只能算补丁。

## 八、常见问题

**Q：NAT 类型是运营商决定的，改路由器有用吗？** 分情况。运营商级 NAT 那一层你改不了；家里的双 NAT、映射策略、UPnP 开关全在你能改的范围内。先看 WAN 口地址再决定往哪动手。

**Q：Type 3 / NAT D 到底能不能玩？** 能玩，能玩的场所有限。D 档只能和 A 档互通，朋友里只要有一个也是 D，你们就连不上。PS 的类型 3 类似，匹配慢、掉线多。

**Q：开了 UPnP 就不用端口映射了吧？** 大多数情况够用，做种这类需要固定端口的场景建议手动映射。另外 UPnP 意味着局域网内任何程序都能让路由器开洞，家里有来路不明的软件时，关掉更稳妥。

**Q：为什么手机热点下 NAT 类型反而更好？** 那是另一条路径，映射策略和出口设备都不同。这类对比只能说明"你家那条路限制更严"，不能说明设备有问题。

**Q：对称型是天生的吗？** 不是。有的路由器把映射策略调成"端口保留"就能改善，有的固件直接没这个选项。刷第三方固件能拿到更细的控制，但前提是你有公网 IP——没有公网 IP 的话，调什么都是对称型。

**Q：怎么确认一个服务商的节点给不给入站？** 两条路：挂载后跑一次 NatTypeTester 看是 FullCone 还是 Symmetric；再找个端口检测页，让它从外部连你的监听端口看通不通。前者看类型，后者看实效。

## 九、三句话

**第一，NAT 类型决定"别人能不能主动找到你"，跟网速无关。** 上传跑满、下载飞快，也可能同时是个入站黑洞。

**第二，先查 WAN 口地址，再看双 NAT，最后才考虑服务商。** 顺序反了，折腾一圈还是原地。

**第三，需要联机就看 UDP 和映射，不需要就别为它加钱。** 大多数人的日常使用，出口严格一点完全够用。
