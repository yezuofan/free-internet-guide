# 讯飞星火 X2.5 上手指南：293B 旗舰与 4B 端侧开源怎么选、怎么接

> 原文：https://huanghaiwan.com/ai/xinghuo-x2-5-guide-2026/

九月上旬，科大讯飞用三天时间放出了三张牌：端侧开源模型、293B 旗舰版、限时五折价格。这三件事单看都不算新鲜，拼在一起才有意思——**一个模型家族同时覆盖云端调用和离线部署，还主动兼容了别家工具的协议。**

**一句话结论：** 旗舰版 293B-A30B 管复杂任务、按量付费（五折期输入 1.6 元 / 输出 6 元每百万 Token）；Spark-X2.5-4B 与 1.7B 开源可商用（Apache-2.0），量化后 2.6GB 起，能离线跑。选哪个不取决于谁分数高，而取决于你的数据能不能出内网、任务复不复杂、要不要接进 Claude Code 一类现成工具。

## 太长不看

| 你的情况 | 建议 | 原因 |
|:---|:---|:---|
| 云端调用、写代码、跑 Agent 工作流 | 旗舰版 293B 的 API | 256K 上下文、原生兼容 Anthropic / Responses 协议，改个端点就能接进现有工具 |
| 数据不能出内网、要离线 | 部署 Spark-X2.5-4B | Apache-2.0 可商用，q4 量化约 2.6GB，6~8GB 显存甚至纯 CPU 能跑 |
| 长文档摘要、翻译、简单问答 | 先试 1.7B 端侧版 | BF16 权重 3GB 出头，四比特量化后减半，普通手机能跑 |
| 英文长文深读、海外 SaaS 调试、多模型交叉验证 | 星火不够用 | 这类任务仍要海外模型兜底 |
| 预算极紧、只想先跑通 | 端侧模型的 MaaS API 目前限时免费 | 先用免费额度验证效果 |

## 一、三天发了什么

- **9 月 1 日**：子公司词元星火在 Hugging Face 开源 Spark-X2.5-4B 与 Spark-X2.5-1.7B 两款端侧模型
- **9 月 7 日**：旗舰版星火 X2.5（293B-A30B）发布，上线讯飞开放平台与星辰 MaaS
- **9 月 8 日**：官方正式宣布旗舰版上线，同步公布限时五折价格

官方口径里，两款端侧模型原生支持最长 100 万 Token 上下文，是端侧模型中少数做到这个量级的；4B 版本开源后不久冲上 Hugging Face 趋势榜第一——这个信号比跑分直观，说明社区真的把它拉下来跑了。

旗舰版的四个关键数字：总参数 2930 亿、每次推理激活 300 亿、上下文 256K、覆盖 200 余种语言。官方强调的升级点是代码生成与智能体（工具调用），不是闲聊质量。还有一个容易被忽略的细节：**全流程训练与推理都跑在国产算力集群上**，对涉密、政企场景来说这是硬门槛。

## 二、价格先看清

| 计费项 | 折后价（元 / 百万 Token） | 原价 |
|:---|:---:|:---:|
| 输入 | 1.6 | 3.2 |
| 输入（缓存命中） | 0.24 | 0.48 |
| 输出 | 6 | 12 |

三点值得说：

1. **缓存命中的差价很大。** 输入 1.6 元、缓存命中 0.24 元，差了近 7 倍。把固定系统提示词和长文档放在前面、让后续请求反复命中缓存，成本会明显低于直觉估算——做 Agent 的人尤其要留意这点。
2. **输出才是大头。** 输出价是输入价的近 4 倍，「先长篇解释再给答案」的提示词写法很贵，直接要结构化输出更划算。
3. **五折是限时。** 别按折后价做长期预算模型，按原价估、按折后价用，是更稳的财务习惯。

## 三、API 怎么接：双协议兼容是最聪明的设计

这次最实用的设计是**原生支持 Anthropic 与 Responses 两种协议**，官方明确提到可快速接入 Claude Code、Codex、OpenClaw 等第三方 Harness 框架——不需要为它单独写一层适配代码。

原理很简单：这类工具都允许把请求地址指向自定义兼容端点。以 Claude Code 一类工具为例，设置两个环境变量即可切换：

```bash
export ANTHROPIC_BASE_URL="<讯飞控制台提供的兼容端点>"
export ANTHROPIC_AUTH_TOKEN="$XINGHUO_API_KEY"
```

端点地址与模型名以讯飞开放平台控制台文档为准，各家兼容层命名会随版本调整，接入前先确认一次。

自己写调用代码则走标准 HTTP 请求：

```bash
curl -X POST "$BASE_URL/chat/completions" \
  -H "Authorization: Bearer $XINGHUO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<控制台中的模型名>","messages":[{"role":"user","content":"把这段财报里的三个异常项挑出来"}]}'
```

三个实操提醒：Key 不要写进代码提交到 Git；先跑通一条最短链路再接 Harness（跳过这步的代价通常是花两小时排查工具配置，结果发现是 Key 没配好）；兼容协议不等于功能完全对等，某些工具的高级特性可能只在原生协议上完整支持，接入后要跑一轮真实任务验证。

## 四、端侧 4B 本地部署要多少显存

| 精度版本 | 文件体积 | 建议配置 |
|:---|:---|:---|
| BF16 原版 | 约 8.2GB | 12GB 显存以上 |
| q8_0 量化 | 约 4.4GB | 6GB 显存起步，8GB 更稳 |
| q4_k_m 量化 | 约 2.6GB | 4GB 显存可试，纯 CPU 也能跑 |

走 llama.cpp 最省事：

```bash
# 从 Hugging Face 或 ModelScope 找到 Spark-X2.5-4B 的 GGUF 仓库
llama-server -m ./Spark-X2.5-4B-Q4_K_M.gguf --ctx-size 32768 --port 8080
# 之后按普通 OpenAI 接口调用 http://localhost:8080/v1
```

Ollama 和 LM Studio 也都支持，图形界面用户可以直接在模型库里搜，具体 tag 名以官方仓库为准。

**这里要说一句可能不太好听的话：官方宣传的「1M 上下文」，在端侧是理论值，不是许愿池。** 1M Token 的 KV 缓存是实打实的显存开销，即便模型用了 1 层全注意力 + 3 层滑动窗口交替的混合架构（官方称长文本显存占用约为传统全局注意力的四分之一），普通 8GB 显卡也撑不住跑满。务实做法是按需设置 `--ctx-size`：日常问答 32K，读长手册 64K~128K，真要用满百万级上下文，那是云端该干的活。

1.7B 版本体积更小，BF16 权重 3GB 出头，四比特量化后还能减半，官方称可在普通手机上运行，定位是手机端的翻译、摘要与简单指令分发。

## 五、实测与跑分：哪些数字要打折

媒体实测里有价值的事实：智东西把星火 X2.5 接进 DeepSeek Harness 做实测，测的是游戏开发这类真实任务；另一篇实测把它接进 Codex 跑了三道任务——生成粒子动画、解析 61 页财报、顺手查出一段代码里的 Bug。

跑分方面，4B 版本官方自测的部分 Agent、编程、数学基准超过 Qwen3.5-9B 与 Gemma4-12B；1.7B 在 MCP-Atlas 拿到 23.4 分（官方称同尺寸最高）；Domux 智能家居测试集上控制指令端到端正确率 90.3%、平均响应 0.85 秒。

**这些数字要打三个折扣：** 一是自测口径，厂商自己跑的分值环境与提示词都可能优化过；二是场景特化，智能家居指令类分高不代表开放域问答也强；三是 Agent 能力受框架影响极大，同一模型接进不同 Harness 表现能差出一截，所以「某模型 Agent 强」最好绑定具体工具一起说。

## 六、和 GLM、Qwen、DeepSeek 怎么选

| 维度 | 星火 X2.5 | 选型时怎么想 |
|:---|:---|:---|
| 算力来源 | 全流程国产算力 | 涉密、政企、有自主可控要求 → 权重最高的一项 |
| 协议兼容 | 原生支持 Anthropic / Responses | 已在用 Claude Code 一类工具、不想改工作流 → 换模型成本最低 |
| 本地可部署 | 4B / 1.7B 开源，Apache-2.0 | 数据不能出内网、要离线 → 只有开源权重这条路 |
| 长上下文 | 旗舰 256K，端侧标称 1M | 长文档是主场景 → 注意端侧实际能跑多少 |
| 生态成熟度 | 相对较新 | 要大量现成教程与社区方案 → 老牌家族仍占优 |

务实组合建议：**主力工作流用你已经在用的那家（迁移成本是真实成本），把星火当「第二意见」和涉密场景备胎。** 多模型交叉验证本来就是降低幻觉的常用手段，多一家国产选择，对做跨境业务的人尤其有价值。

## 七、跨境链路的现实问题

要说清一个容易混淆的点：**用国产模型本身不需要任何跨境网络**，星火的 API 就在国内，直连即可。

但现实里很多人是这么用的：把星火接进 Claude Code、Codex 这类 Harness 当后端模型，而这些工具本身以及它们默认的海外模型调用需要稳定的国际链路；或者一边用国产模型处理内部资料，一边用 Claude、GPT 读英文长文档、调试海外 SaaS 的 SDK。长时 Agent 任务跑到一半断线，几小时的上下文直接作废，这类损失不是「重试一次」能补的。

所以如果你的工作流是「国产模型 + 海外工具」的混合形态，一条稳定的国际网络链路仍然是前置条件，不是可选项。

## FAQ

**Q1：免费额度够用吗？** 端侧模型对应的 API 目前限时免费，旗舰版是五折付费。个人试水用免费额度足够验证效果；进入日常使用后，按量付费比到处找免费额度更省时间。

**Q2：4B 能替代云端旗舰吗？** 不能，也不该这么比。4B 的价值是离线、私有、零调用成本，适合长文档解析、本地知识库问答、简单脚本生成。正经复杂编码任务，27B 以下普遍吃力，这是社区共识口径，不是某一家的短板。

**Q3：1M 上下文是噱头吗？** 不算噱头，但要看代价。原生支持百万级意味着架构上做了准备，实际能用多少取决于显存与 KV 缓存预算，云端按量付费的旗舰版更能发挥这个能力。

**Q4：本地部署难吗？** Ollama、LM Studio 已经把下载、量化、加载封装好了。真正需要判断的是三件事：选哪个量化版本、上下文开多大、显存够不够。

**Q5：企业用它要注意什么？** 数据边界第一。不管走云 API 还是本地部署，先确认数据存放位置、保留期限、是否用于训练。功能可以后补，数据边界出问题很难补救。

**Q6：迁移成本高吗？** 如果工具支持自定义兼容端点，成本主要在验证环节；如果从头写调用代码，还要考虑提示词适配与评估基线重建——那才是真正的迁移成本。

**Q7：现在入场会不会太早？** 不算早。旗舰版已上线开放平台、端侧已开源可下载，官方还提到会在 1024 开发者节推出基于全国产算力的新一代主力模型。现在跑通一条链路，将来迁移成本很低。

**Q8：和 DeepSeek 比谁更强？** 没有稳定答案，两者迭代都快。判断标准是「我的任务上谁更稳」，而不是「谁分数高」——自己拿三件真实任务各跑一遍，结论比任何评测可靠。

## 总结

1. **它不是单点产品，是一个家族。** 云端旗舰管复杂任务，端侧 4B / 1.7B 管离线场景，两套价格体系覆盖从个人到政企的不同预算。
2. **双协议兼容是这次最聪明的设计。** 降低迁移摩擦，比多几个基准分更能换来真实用户。
3. **国产算力全流程跑通的意义在特定场景才显现。** 对普通用户是背景信息，对政企和涉密业务是决定性的。

先拿一件手上真实的麻烦事去试。唯一要提醒的是：宣传口径里的「1M 上下文」「同尺寸第一」，都是起点不是结论，自己跑一遍才算数。
