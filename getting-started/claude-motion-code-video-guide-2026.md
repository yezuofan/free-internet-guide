# Claude Opus 5.5 不会做视频，却让一批人把视频“写”了出来：Claude Motion 官方指南与代码视频五步流水线（2026）

**2026 年 10 月更新。** 打开 Claude Opus 5.5 丢一句「帮我做条 30 秒产品视频」，等不来 MP4——它是文本与代码模型，输出的是文字和代码。这个 10 月，Anthropic 用 Claude Motion 把「用代码做视频」这条路官方收编了：**在 Claude Code 环境里由 Opus 5.5 调用 HyperFrames 框架写动效代码，并自行渲染导出 MP4**。下面把认知、路径、流水线、坑和网络前提一次讲清。

| 最好的第一次尝试 | 先做 5 秒、720P 的一条把链路跑通，再放大到 1080P / 一分钟以上 |

## 一、认知摆正：这是「代码视频」，不是「文生视频」

文生视频（Sora、Kling 可灵、Runway 那一类）爽点在「无中生有」，痛点叫**抽卡**：改一句旁白整条重生成，要三个版本出来三个风格，想微调某一秒停顿整段画面跟着变形。做宣传片的人最懂这种折磨——品牌部要的从来不是「有画面」，而是**可复用、可改参数、VI 保持一致**。

代码视频走另一条路：模型输出的是一份可读、可改、能进版本管理的代码。画面排版在 HTML / CSS 里，数据与时间轴在 JavaScript 里，运动曲线用参数定义，最后按固定帧率逐帧截取，用 FFmpeg 编码成 MP4。代价是失去「无中生有」，换来的是**每个字、每个数字、每个时间点都能被精确定位和修改**。

| 维度 | 文生视频模型 | 代码视频 |
|:---|:---|:---|
| 输入 | 一段提示词 | 需求 + 文档 / 数据 / 截图 + 代码 |
| 改一个词 | 大概率整条重生成 | 只改对应那一处 |
| 一致性 | 靠抽卡，风格会飘 | 配色字体 Logo 按配置走，天然一致 |
| 批量生产 | 每条都要等、都要抽 | 换数据文件再渲染一遍 |
| 真实人物 | 可以 | 基本不行 |
| 计费 | 按生成次数 / 时长 | 按 token + 自己机器的渲染时间 |
| 适合什么 | 概念片、氛围镜头、实拍风格 | 数据动效、产品讲解、科普动画、品牌片头、Logo 演绎 |

一句话分工：**要「像拍出来的」交给文生视频；要「能改、能复用、能批量」交给代码视频。**

## 二、这波为什么是 Opus 5.5 带起来的

时间线很说明问题。**9 月 22 日** Anthropic 发布 Opus 5.5，官方文档没有一段提到视频或图像生成，重心在编程能力与 Agent 任务执行，官方称运行成本比上代 Opus 5 低约 40%；**9 月 28 日** Sonnet 5.5 补齐通用执行档；**10 月 7 日前后** Haiku 5.5 把短上下文价格砍了九成。半个月三款，价格战打得很凶。

真正的意外在发布之后。开发者发现这个模型的**代码稳定性与任务规划能力**足以把「用代码画动画」从玩具级推到能交付：作品先在 X 上集中出现，随后蔓延到小红书、抖音——有人十二小时做出一部反乌托邦风格叙事短片，有人拿它生成产品发布视频、科普讲解动画，也有人做出带粒子特效与音频同步的 Motion Graphics。**不到一周，开源社区整理出数百套提示词**，按动画、3D 场景、交互效果分类归档，还有站点把作品、作者、原始提示词与用到的 Skill 放在一起给人抄作业。

**10 月 8 日到 9 日**，官方下场，上线 Claude Motion 与面向 BI 的 Dashboards。官方定位说得直白：不走视频生成模型，而是**写代码驱动你的文字、图表、几何形状和静态截图做动画**，原话是「没有生成的画面，也没有 AI 生成的人」；可在编辑器里改，也可以让 Claude 改，最后导出 MP4。**10 月 10 日**官方放出完整上手指南。

热度还外溢了：同一周一批老游戏被用同样思路搬回浏览器，网页版《光环：战役进化》上线五小时跑出接近两万场对局、一百多个国家的玩家涌进去，《GTA：罪恶都市》《滑板 3》也陆续被重制上线，随后法务函到场、项目下架——这条插曲对做内容的人是条很实在的边界提醒。

## 三、三条落地路径

### 路径一：官方 Claude Motion（最省事，先试这条）

适合手上已有文档、报告、图表，想快速产出讲解动效、不想碰代码细节的人。官方指南给的用法很具体：只需告诉它三件事——**这段视频做给谁看、放在哪里播、大概多长**，再把项目说明文档、落地页内容、新手引导流程、最新更新日志、真实数据图表一并附上，让它自己读、自己找亮点。官方举的落地场景也很接地气：把季度报告做成全员大会上的 30 秒讲解、给董事会 PPT 的图表加动效、做一段给新客户看的引导短片。官方指令骨架大致是：

> 参考 Claude Motion 的操作思路，通读当前项目的说明文档、落地页、新手引导流程、最新更新日志和数据图表，从中找出三类最值得做成动效的内容，先给我一个分镜清单和每段时长，确认后再开始写代码。

注意最后半句——**先要分镜清单，再让它写代码**，这是全套流程里最省返工的一步。

### 路径二：自己写代码（最自由，也最需要耐心）

适合有明确品牌规范、要批量产出、或要把生成流程接进自己系统的团队。核心是选对渲染路线：

| 路线 | 技术栈 | 出片形态 | 适合谁 |
|:---|:---|:---|:---|
| HTML / CSS / JS + 无头浏览器逐帧截图 + FFmpeg | 前端三件套 | 版面动效、文字动画、图表 | 前端出身、要精细控制 |
| HyperFrames | HTML 排版 + CSS 动效 + JS 数据与时间轴 | 网页形态的短视频 | 想用现成框架省事的人 |
| Remotion | React 组件化 | 数据驱动、模板化视频 | 做批量视频矩阵的团队 |
| Playwright + ffmpeg | 浏览器自动化 | 结构简单、依赖少 | 不想引入 React 的人 |
| Python 绘帧 + FFmpeg | matplotlib / PIL + 编码器 | 图表、数据可视化 | 数据分析、报表转视频 |
| Three.js / WebGL | 3D 场景 | 空间感、粒子、产品旋转 | 做视觉冲击的创意向 |
| Blender 脚本 | 3D 渲染管线 | 片头、Logo 演绎 | 有 3D 基础的人 |

一个能说明手感的具体例子：把 CSV 里三类数据做成 12 秒、1280×720 的 MP4，做法是 Python 逐帧绘制、FFmpeg 编码。这类项目里有条细节值得记——**屏幕上柱条逐渐变长，不应该被包装成「业务指标随时间增长」**：原始计数不要随动画改变，动画只表达过程、不篡改数字。

### 路径三：抄现成的作品库和技能包（最快出成果）

那批站点的价值在于**提示词和成品是配对的**：看到喜欢的效果，点进去能拿到作者公开的指令原文，有的还标注用了哪个模型、开到什么推理强度。社区也已把「自动做动效视频」打包成可复用技能：有的自带审美检查、会自己回看画面帧、还能用代码生成音频；有的用 HTML + 浏览器自动化 + FFmpeg，刻意不依赖 React 那套。抄作业的正确姿势是**先抄结构，别抄文案**——把别人的流水线拆成环节，自己的数据和品牌换进去，跑一遍看哪一步翻车。

## 四、五步流水线：每步给什么、查什么

**第一步，拆需求。** 别从「做个视频」开始。观众是谁、在哪播（手机竖屏还是会议室大屏）、多长、什么调性、必须出现哪些数字。合格输入长这样：给财务部门的季度回顾，会议室投影播放，40 秒左右，语气克制，必须出现营收、毛利率、客户留存三个数字。

**第二步，要分镜清单，别要成品。** 让它先输出文字版分镜：第几秒到第几秒、画面出现什么、动什么、配什么文案、每段多长。几分钟就能拦住大部分方向性错误，比看到成片再推翻便宜太多。

**第三步，写代码时一次性要求「参数化」。** 这是代码视频最值钱、也最容易白费的地方：必须一开始就要求把**文案、数字、配色、字号、时长**抽成配置对象或参数，而不是散落在函数里硬编码。做到了，改一个字是微调；没做到，改一个字就是重跑全片，你又回到抽卡时代。

**第四步，渲染先小后大。** 1080P、30 帧、30 秒就是 900 帧，逐帧截图的开销是实打实的时间。先出 5 秒、720P 样片，确认画面、字体、节奏都对，再放大分辨率与时长。

**第五步，编码别省事。** H.264 加 yuv420p 兼容性最好，手机、微信、网页、剪辑软件通吃；码率与分辨率要匹配；帧率全线保持一致，别在中途被默认值改掉。导出后用手机看一遍——电脑上正常、手机上一片黑并不罕见。

## 五、官方指南里最实用的三点

1. **明确了「不做生成画面」。** 官方原话：没有生成的画面，也没有 AI 生成的人。这既是能力边界也是选型依据——真人出镜、实拍质感、氛围空镜别指望它；图表、数据、版面、文字、几何形体的动效它又稳又准。
2. **圈定了三类最值得做动效的内容**：数据图表与关键指标、产品更新与功能亮点、新用户引导流程。共同点是「内容已经在文档里了，只是需要一个会动的表达」。
3. **把输入材料的重要性摆在模型技巧之上。** 你给的文档越真实、数据越具体，它挑出来的东西越能用；只丢一句「做个酷炫的视频」，出来的必然是一堆热闹但落不到业务上的空镜头。

## 六、八个必踩的坑

1. **以为一句话就有 MP4**——模型不产出像素，产出的是代码与指令。
2. **低估渲染时长**——逐帧截图是实打实的计算量，先用 5 秒 720P 验证链路。
3. **中文渲成方块**——无头浏览器环境常缺中文字形，页面预览正常、渲出来全是豆腐块，需显式指定字体或把字体文件带进项目。
4. **帧率与时长没对齐**——24 / 25 / 30 帧都常见，但全线必须统一，中途变一次音画立刻错位。
5. **音频对不上**——正确顺序是**先有音频、再排画面**，让画面贴音轨，而不是把音频硬塞进画面。
6. **改一个词整片重来**——回到第三步的参数化纪律，丢了它就白走这条路。
7. **模型忽好忽坏就怀疑自己**——本月另有报道称 Opus 5.5 被路由到另一个更强的模型上，官方未回应。实用建议是：同一份提示词昨天今天差别很大时，**先确认请求实际落到哪个模型、推理强度什么档**，再怀疑自己的提示词；把「模型变了」误判成「网络坏了」最容易白折腾半天。
8. **版权别等法务函**——配乐、字体、Logo、影视素材、明星形象各有授权口径，平台对 AI 生成内容的标注也有要求。

## 七、最后那关：链路稳不稳，决定这套流程能不能用

真正把它跑成日常产出的人会发现，卡住产出的往往不是模型而是网络。三个层次，一个比一个隐蔽：

- **能不能开**：打开 Claude、跑 Claude Code、上传素材文档、回传成片，都要跨国链路配合。这层最好发现。
- **账号环境前后是否一致**：平台判断风险不是看你出口 IP 是什么，而是看它跟**上一次**比变了多少。频繁登录控制台、一会儿家里一会儿公司一会儿手机热点，在风控眼里就是三个地区的登录环境在同一个账号上打架，反复验证、限流、封号接踵而来。**管账号的那条链路，出口归属的一致性比速度重要得多。**
- **长任务怕断**：代码生成一轮可能十几分钟，逐帧渲染更久，一次跨小时任务抖一下、断开重连，前面跑完的可能白等。**这类场景稳定性比峰值速度重要得多。**

另外两个高频误判：**浏览器能开、命令行工具连不上**——命令行、后台服务、部分客户端不读系统代理，自己实现网络栈，「网页正常、客户端一直正在连接」九成出在这里，补上代理设置或切 TUN 模式让流量在系统层被接管通常当场解决；**别在白天测完就下结论**——晚八点到十一点是国际出口最堵的时段，上传素材、回传成片往往正好落在那个窗口，要测就挑那个时段测。

## 八、开工前自查清单

- 想清楚观众、投放位置、时长，写进第一句话
- 先要分镜清单，确认后再让它写代码
- 明确要求把文案、数字、配色、时长抽成可配置参数
- 第一次渲染从 5 秒 720P 开始
- 中文字体提前指定，别等渲出方块
- 音轨先定，画面后贴
- 导出用 H.264 加 yuv420p，导出后用手机看一遍
- 长任务前确认链路在最堵时段稳不稳
- 素材版权、字体授权、AI 内容标注，发布前过一次

## FAQ

**我没有编程基础，能用吗？** 能。走官方 Claude Motion 基本不用碰代码，你负责把文档、数据、要求说清楚。需要补的不是编程，是几个概念：帧率、分辨率、码率、音轨。

**它和 Sora、可灵这类视频模型是竞争关系吗？** 分工关系。真人、实拍、氛围镜头交给文生视频；数据动效、产品讲解、品牌片头、批量模板交给代码视频。

**成本大概多少？** 两块：模型 token 费用 + 自己机器的渲染时间。费用重心通常在反复调试而不是最终那次渲染，所以「参数化」既省事也省钱。

**生成的视频能商用吗？** 工具不构成障碍，障碍在素材——喂进去的字体、音乐、Logo、影视片段，授权得自己确认；不少平台还要求对 AI 生成内容做标注。

**渲到一半失败怎么办？** 先降规格重跑确认代码没问题，再查是渲染环境（字体、内存、浏览器版本）还是链路问题；如果失败总发生在长时间渲染的后半段，多半是连接被中断。

一、Opus 5.5 不做视频，它写代码；视频是代码渲染出来的，这件事在这个月被官方用 Claude Motion 收编了。
